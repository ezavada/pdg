Programmed transforms and schedule controls

setScale(x,y) (or a uniform setScale(factor)) sets independent dimensionless scale; changeScaleTo(x,y,seconds,easing) transitions it. getScale() returns a fresh Offset. Logical width/height, resizeTo(), grow() and stretch() retain their size meanings. Negative scale reflects an axis, and flip flags combine with its sign. Zero scale is valid for display; inverse coordinate queries reject singular transforms. Sprites use this same API for both image and Spriter artwork. Imported asset normalization is private; Animated scale and ancestor transforms each apply once.

setGrowing(rate) and setStretching(xRate,yRate) immediately set constant logical size changes per second. changeGrowingTo()/changeGrowingBy() and changeStretchingTo()/changeStretchingBy() transition these rates over explicit seconds. The final rate continues after the transition. getStretching() returns the current two rates as an Offset. Size setters preserve growth rates; stopGrowing()/stopStretching() cancel growth-rate and scheduled size changes. These rates are programmed animation, without physical damping or forces.

pauseSchedule()/resumeSchedule() freeze/resume scheduled transitions and their delays. They do not stop helpers, constant movement/spin/growth, Sprite clips or physics. A paused rate transition holds its current rate while that motion continues. cancelSchedule() discards scheduled targets and the pending wait, holding sampled values and preserving the paused state. It emits no completion notification. hasScheduledAnimations() includes delayed and paused transitions; isSchedulePaused() reports the independent clock state. AnimatedAttributes includes appearance and frame tracks in these controls.

Sprite snapshots preserve scale, scale/growth transitions, pause state and the pending wait in animation record revision 3. Layer update snapshots also preserve active tween tracks, directed rotation, rate transitions and pending waits. Standalone Animated records preserve its transform, rates and tween state; subclass artwork/appearance/controller records are separate. Full Layer graph reconstruction remains incomplete. Rect-returning Layer conversions use conservative axis-aligned bounds when independent scale or reflection is active; use the Quad overloads for exact corners, including shear. Explicit collision radii, body mass and inertia are unchanged by visual scale; Sprite bounding-box shapes follow scaled dimensions.

Build capabilities

Spriter playback and the Sprite pose, modifier, IK, physics, and drawing entry points require PDG_SPRITER_SUPPORT. Enable pose evaluation with pdg::Sprite::enableAnimationPose() before using the pose-based Sprite extensions. Physics simulation additionally requires PDG_USE_CHIPMUNK_PHYSICS; query pdg::Sprite::supportsAnimationPhysics() for build support. Drawing replay requires a GUI-capable build; query pdg::Sprite::isAnimationDrawingSupported(). Rig and pose data, pose modifiers, and target helpers can be used without rendering.

The C++ reference includes the optional Spriter and Chipmunk interfaces so they remain discoverable. Their presence in these pages does not enable them in an application build.

The authored-trigger payload is listed under Events, Animation, and Sprites. Use triggerName to identify its authored track. timeSeconds is relative to clip start; offsetSeconds is relative to the current update. The inherited action field is not used to identify triggers. Subscribe to the trigger event type and inspect its authored name. Blend completion covers both pdg::Sprite::blendToAnimation() and pdg::Sprite::transitionToAnimation(), independently of authored-trigger enablement.

Animation timing

Floating-point seconds are the current animation timing convention.** For example, pass 0.25 for a quarter-second blend, sample time, transition duration, contact-release duration, or physics-recovery duration. Modifier callbacks receive elapsed seconds in pdg::AnimationModifierContext::deltaSeconds.

Timed Animated operations, wait(), sprite fades, layer fades and camera zoom, IAnimationHelper::animate(), and built-in/custom EasingFunc callbacks now use floating-point seconds. Physical forces and velocities belong to PhysicsBody; Animated contains only programmed transform changes.

The remaining millisecond boundaries are:

Existing API or field Current time units
pdg::SpriteLayer::animateLayer() ms_delta msElapsed; this layer scheduler entry point still takes milliseconds and converts to seconds for Animated stepping
pdg::SpriteLayerInfo::millisec Integer millisecond timestamp
pdg::SpriteTriggerEventInfo::frameTime Compatibility integer millisecond field; use timeSeconds for authored clip time and offsetSeconds for the occurrence offset within the update
pdg::TimerManager::startTimer() and general event timestamps Milliseconds; convert elapsed intervals explicitly when driving animation

Do not infer units from a number's magnitude. When migrating an older caller of a now-seconds API, convert its millisecond duration by dividing by 1000.0.

Frame indices and counts are integers, startFrameAnimation() takes frames per second, and animation/blend progress is a dimensionless fraction. These are not time-duration arguments. Angles in pose transforms are radians; fixed choices such as pdg::AnimationSpace use integer enum constants. Clip, bone, and slot names remain strings.
