Detailed Description

Shared animation state and polymorphic interface.

Use Animated<T> for fluent methods that return the concrete owner type.

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

◆ addAnimationHelper()

AnimatedBase & addAnimationHelper ( IAnimationHelper * helper)
inline

Register a callback after the object's normal animation step.

Helpers run in registration order and receive elapsed floating-point seconds. Returning false retires that registration. Adding an already registered helper is an idempotent operation. A helper may be registered on several owners.

Removing or clearing helpers inside a callback skips their remaining calls on this step. Newly added registrations run on the next step. Removing and re-adding the current helper creates a new registration; returning false only retires the old one.

Parameters
helperNon-null callback object. If ownedByAnimated() returns true, each owner retains a native reference until registration ends and any executing callback returns. The final release deletes the helper. Keep your own addRef()/release() reference if you intend to reuse a helper after retirement. A borrowed helper (ownedByAnimated() returns false) must outlive its registrations and executing callbacks.
Returns
This object, for chaining.
See also
removeAnimationHelper(), clearAnimationHelpers(), IAnimationHelper

◆ andAlso()

AnimatedBase & andAlso ( )

Join the following operand to the preceding parallel chain.

Returns
This object for chaining. Requires a preceding operand that has not activated and a following operand. Repeated calls extend an implied batch. Following until(), yoyo(), repeat(), timing, amplitude and playback controls select that complete chain. Inside a series, the chain is one step and the next ordinary operand waits for every member to complete. Pending explicit andThen() placement is incompatible with andAlso().
Example
target.series().moveBy(100, 0, 2).andAlso().rotateBy(1, 2)
.endSeries();
See also
batch(), until(), series()

◆ andThen()

AnimatedBase & andThen ( )

Start the next timed operation after the most recently scheduled operation finishes.

Uses its remaining duration and delay, not the longest of all concurrent operations. The next request consumes this sequencing state; later calls again run concurrently unless sequenced. A successor acquires its properties and resolves relative targets when it starts. Immediate calls after andThen() throw even if the predecessor has finished. No then() method is provided, so returning an Animated object from an async JavaScript function is safe.

Returns
This object, for chaining.
See also
wait(), cancelSchedule()

◆ on()

AnimatedBase & on ( const std::string & event,
AnimationEventHandler handler )

Observe a selected animation block's lifecycle.

Parameters
eventA custom nonempty event name, or started, finished, scriptFinished, mark, yoyo, repeat or untilFired.
handlerCallable receiving const AnimationEvent&. Its return value is ignored.
Returns
This object for chaining.

Registration applies to the selected operand, or to the current empty recorder/block before its first operand. Multiple handlers run in registration order. Register after a modifier to observe that modifier. Named definitions retain their handlers; each invocation has its own playback state. Registration does not emit events retroactively.

started and finished describe only the selected block. Other events propagate from children to enclosing blocks. finished means successful natural completion or completion through until(); stopIt() and channel cancellation do not report success. scriptFinished identifies completed named invocations, including nested invocations. yoyo fires at the forward-to-reverse turn; repeat fires before each additional iteration, starting at iteration 1. untilFired fires only when the condition ends the operand early; natural completion does not emit it. mark fires whenever a mark is reached, including repeat visits.

Handlers run synchronously after each scheduler substep publishes state, in traversal order. A handler may change the target or start another animation. The target reflects published state at delivery, which can be later than the individual event boundary when a substep crosses several events. Handler exceptions propagate to the caller; already delivered events are not replayed. Context and target are borrowed for the callback; copy the scalar fields if they are needed later. Handlers are runtime resources and reject portable snapshots.

For Troupes, finished on the collective block fires once after all members complete. Events inside staggered member scripts identify that member as target.

pdg::Animated<> actor;
actor.moveBy(100, 0, 2).andAlso().rotateBy(1, 2)
.until([](const pdg::AnimationEvaluationContext& context) {
return context.target.getLocation().x >= 50;
}).on("untilFired", [](const pdg::AnimationEvent& event) {
event.target.moveBy(0, -20, 0.5);
});
actor.animate(1);
actor.animate(0.5); // interruption handler starts the upward move
