Sprite & attachAnimationPhysicsPart ( Part * part,
Part * parent = nullptr )

Register a same-Sprite physical Part in the rig assembly; joints are explicit.

Register a physical Part in a physical rig's mass assembly.

Adds the Part's existing mass to physics.getMass(). No other body's mass or inertia changes. The Part must belong to this Sprite and already have a body. An accessory must have no Part parent, bone/slot/socket binding, or mounted Sprite. Its current control mode is retained. Skeletal Parts previously detached from this rig can be registered again; they start Dynamic.

The optional parent records assembly hierarchy for subtree detachment. It does not create a joint, move a body, bind artwork, or claim an animation drive. Create joints explicitly with PhysicsBody. For skeletal Parts, the nearest attached skeletal ancestor is automatic, and an explicit parent must match. For accessories, an omitted or null parent means an independent assembly member. Registering the same Part again is harmless; changing its parent requires detach.

Only registered bodies contribute to the total; arbitrary joint connectivity never adds mass. Whole-rig animation modes and recovery select attached skeletal bodies. An accessory keeps its own body control, responding through its joints.

Returns

◆ detachAnimationPhysicsPart()

Sprite & detachAnimationPhysicsPart ( Part * part,
bool includeDescendants = true )

Release membership/control and disconnect boundary joints, preserving internal joints.

Release a Part or subtree from the physics assembly.

Removes the selected members' masses from the Sprite total without redistributing any mass or inertia. Skeletal bodies become Dynamic and stop following animation; artwork continues following their physical bones. Body identity, pose, velocity, collider geometry and collision filters are retained. Joints within the selected set remain intact; every joint crossing its boundary is disconnected, including connections to external bodies. Retained disconnected constraint handles are safe to inspect but report inactive.

Descendants follow assembly hierarchy, including registered accessories. With includeDescendants false, surviving children are logically reparented to the nearest surviving ancestor; no replacement physical joints are created. Detached bodies are excluded from whole-rig control, recovery and aggregate mass edits. Address them directly through their Part's physics object.

If the selected root leaves, the remaining attached skeletal bone named root is preferred, otherwise the one with the most assembly descendants (ties use body definition order). Whole-Sprite impulses and root follow use this replacement. At least one skeletal body must remain; disableAnimationPhysics() tears down the whole rig. Detaching a nonmember is a no-op.

This releases assembly membership, not Sprite ownership. Parts and bodies remain alive while this Sprite/rig does. Disabling the rig removes all originally mapped bodies, including detached ones. Ordinary accessory Parts retain their bodies but stop contributing to the aggregate. Removing an accessory Part or its body also removes its membership. Mapped Part removal still requires rig disable; transferPart() can instead release mapped bodies into another Sprite.

void serialize ( ISerializer * serializer) const
overridevirtual

Write selected Sprite state to a data stream.

Parameters
serializerDestination writer; not null. The owning layer selects state flags; an off-layer Sprite uses ser_Full. Initial animation/image records include frame artwork, collision masks, frame layout and fractional playback position. Shared images remain shared. The writer's ISerializer::setResourceMode() selects embedded pixels or external image references. Corresponding state flags include programmed transforms/tweens and PhysicsBody state, including active drives. Timing uses floating-point seconds.

Updates with ser_Animations (including ser_Update) transfer sampled local Part transforms, reflection, constant movement and scheduled animations by Part ID. They preserve existing Part identities, parent links and artwork. This includes poses already solved by Part IK. The receiver can stop Layer animations and disable collisions to display only the received state. Part creation/removal, reparenting, artwork changes, IK controller configuration and Part body/constraint state require another initial snapshot; incremental Part records are not full physics checkpoints. A changed Part ID set is rejected.

Initial records also preserve independent Parts: IDs/names, parent links, local transforms, paused/active tweens, bodies and active drives. Part Image/Drawing content retains geometry, attributes, nested drawings and shared images. Drawing content is embedded in both modes; its images follow the selected resource policy.

Drawing colors and image transparency colors use eight-bit channels, with opaque alpha omitted. Floating-point colors can change by less than one channel step (1/255) when restored. Image pixel data is preserved exactly. Drawing geometry, pixel-space attributes (including thickness, text size, offsets and transform translation), and image subsections use the compact coordinate serializers. These can discard a fractional remainder smaller than 0.001 per encoded coordinate component. Rectangles encode their origin and size, so those small errors can accumulate at the opposite edge. Physics state, collision geometry, constraint anchors, IK inputs and Sprite/Part transforms retain their existing floating-point precision.

Packed boolean flags omit default values and absent payloads. Repeated images, Drawing storage and imported animation assets use shared object references within the same serializer stream. This preserves shared identity and avoids writing the same resource again; independently created objects remain distinct.

Imported SCML animations retain their shared model, selected entity/clip, floating-point playback time, pause/events, character maps, reference pose, bone overrides, blends and interrupted transitions. Bone-, artwork- and socket-bound Parts resolve against the restored rig. Built-in rig IK modifiers and retained Drawing registrations preserve their IDs, options and enabled state. Animation colliders continue following the restored pose.

Complete saves embed the imported document and its images and can load without the source files. Embedded XML is compressed losslessly with zlib when that makes it smaller; decompression is automatic. Documents are limited to 64 MiB before compression, and corrupt payloads or mismatched lengths cause a load error. External-reference saves omit the XML, resolve the original document path and verify that its contents have not changed; images use the selected resource policy. Missing or changed dependencies cause a load error.

Initial records preserve Collider shapes and shape IDs, frame/animation-source options, material overrides, collision filters, sensor/enabled state and contact-event opt-in. Compound-body associations, all PhysicsConstraint types, linked IK limits and active physical Part IK controllers resolve after all owners exist. Captured IK offsets and sampled drives survive; offsets are not recaptured from a deformed pose. Geometry is stored in both resource modes; frame images follow the resource policy. Restored colliders receive new process-wide IDs. Body angular-speed break thresholds, reference identities and notification latches also survive. Relative references must belong to the saved graph; a reported excursion does not repeat on restore. Native PhysicsBody break callbacks must be cleared before saving.

Initial records also preserve active physical rigs created from explicit configurations or generated skeletons. They save edited body/collider/constraint components, bone mappings, root selection, attached/detached membership, aggregate mass, desired poses, Kinematic/Dynamic/Driven modes, manual drive targets, rig drive settings and recovery progress. A pending recovery or disable resumes with its remaining duration and completion notification; a completed recovery is not reported again. Load into a Chipmunk-capable build and use a physics-enabled layer to continue simulation. A standalone restored Sprite can be inspected before adding it to a layer. These records preserve engine state, not application callbacks; re-register application logic after loading. Save at an unlocked physics boundary. Layer initial restores validate the staged graph before replacing the live scene. Incremental motion updates are not rig checkpoints.

Callback collision filters/handlers are rejected; reinstall application handlers after loading. Solver contact caches and pending contact events are not saved, so loading rebuilds contacts and can produce new Begin events. A resumed simulation is not guaranteed to be bit-for-bit identical to an uninterrupted one.

Standalone Sprite saves reject attachments; save their owning SpriteLayer to retain mount relationships and cross-Sprite physical links. Select animation control for a physical rig or its bones.

Kinematic follows the desired animation/IK pose using swept bodies. Dynamic releases rig tracking and lets physics determine the pose. Driven keeps dynamic bodies and applies bounded tracking forces and torques. Mixed is query-only. Changing control preserves body, collider and joint identities, mass, velocities and independent scheduled loads. Kinematic-to-kinematic joints remain configured but dormant. A single selected body can still be restrained by its neighbors.

Selections use the skeleton hierarchy, including skipped bones. An included bone may be selected alone; a skipped bone may select included descendants. Missing bones or selections with no physical bodies throw. The entire selection is validated before any control changes. Driven requires configured drive settings on every selected body.

A body has one controller. Before rig tracking takes over, release a manual drive with PhysicsBody::clearDrive(), or release a physical Part IK chain with Part::clearIKTarget(). To release rig tracking, select Dynamic. Raw clearDrive() and manual setDriveTarget() cannot replace rig-owned control. Repeated manual setDriveTarget() calls are allowed after release: the last valid call wins. Direct mapped-body physics.setMode() uses the same coordinator: Dynamic releases rig tracking, Kinematic requests default recovery, and Static throws.

Driven limbs track their desired transform relative to the nearest included physical ancestor. Reaction forces and torques act on dynamic parents; free limbs are not independently pinned to world coordinates. Bodies without an included ancestor track an animation root target in world coordinates. Solver-followed Sprite translation does not move that target. Rotations use physical body frames, including the reflected reference pose. Resolved angular routes persist across ticks; AsSpecified preserves unwrapped turns. Physical joint limits remain binding.

Positive recoveryTime blends the requested target from the current physical pose. During recovery, the affected bodies remain dynamic and getAnimationPhysicsMode() reports Driven, including when the destination is Kinematic. The requested time is a minimum transition duration: completion waits until position error is within 0.1% of segment length (at least 0.000001 layer units) and angular error is within 0.001 radians. Contacts, joint limits or insufficient force may delay completion indefinitely. PhysicsBody::getDriveState() reports the target and actual error; normal collision events report contacts. There are no recovery-start or blocked events. Pausing animation does not pause physical recovery.

Recovery uses bounded integral correction to remove steady gravity/load error, within the same force and torque caps. Recovery uses stored drive settings if available. For an unconfigured transition to Kinematic only, a temporary 4 Hz, critically damped servo uses force capped at mass * max(segment length, 0.001) * (2*pi*4)^2 and torque capped at inertia * (2*pi*4)^2. This does not configure the persistent drive-settings record. Configure settings explicitly to tune those bounds. Zero recoveryTime takes control immediately; Kinematic moves to the requested pose, while Driven starts its bounded drive immediately. Dynamic release is always immediate.

Overlapping mode commands cancel the old selection's completion notification; unaffected bodies can finish their existing recovery. Any new mode command cancels a pending disable. A completed selection emits one Sprite::action_AnimationPhysicsRecoveryComplete event on eventType_SpriteAnimate, with SpriteAnimationPhysicsRecoveryInfo: actingSprite, inLayer, id, bone, wholeRig, includeDescendants, mode, bodyCount and disabled. wholeRig means bone is animation_NoBone. Immediate takeover completes at the next physics update; disableAnimationPhysics(0) completes synchronously after teardown.
