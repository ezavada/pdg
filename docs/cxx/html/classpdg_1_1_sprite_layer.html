Detailed Description

Collection of sprites with shared animation control and layer transforms.

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

◆ addSprite()

virtual void addSprite ( Sprite * newSprite)
virtual

Add a Sprite and its mounted descendants to this layer.

Transfers the group from its previous layer when necessary, preserving its layer-coordinate transforms and mounting relationships. Inserts the host first, followed by descendants, in front of existing sprites. A Sprite already in this layer is unchanged. Use Sprite::moveBehind() or Sprite::moveInFrontOf() to change one member's draw order.

Parameters
newSpriteThe Sprite to add. An attached child must first be detached with Part::detachSprite(); otherwise the call throws without changing either layer. A null pointer is ignored.
Note
Transfer must occur outside animation modifiers and locked physics callbacks. Root constraints and physical animation rigs are disconnected on removal; ordinary Parts, artwork and modifiers remain associated. Imported Spriter sprites retain their shared model and artwork independently of the source layer. Destroying that layer preserves transferred or retained sprites, including their playback, bone bindings and modifiers.
See also
removeSprite(), Part::attachSprite()

◆ deserialize()

void deserialize ( IDeserializer * deserializer)
overridevirtual

Restore Layer state or apply an incremental update.

Parameters
deserializerReader positioned at a SpriteLayer record; not null. Initial records load into an empty or populated Layer, preserving shared resources, independent Part graphs and Sprite order. Mount links are validated after creating the entire collection, including cycle/duplicate-owner checks. Record/resource validation completes before replacing live membership and state. Retained old sprites are detached; restored bodies join the solver after validation. Camera tween pointers, including zoom, are rebound to the restored camera. Shared explicit cameras retain identity within one stream. A validation failure preserves existing state; discard the failed reader.

The destination keeps its Port, event handlers and caller-selected serialization flags. Incremental updates require matching sprites and are applied directly.

Note
Call outside animation modifiers and a physical solve. The shared physical world is not recreated; configure gravity and damping in the application.
See also
SpriteLayer::serialize(), SpriteLayer::setSerializationFlags()

Implements ISerializable.

◆ removeSprite()

virtual void removeSprite ( Sprite * oldSprite)
virtual

Remove a Sprite and its mounted descendants from this layer.

Preserves mount relationships and layer-coordinate transforms. Retained groups can be animated off-layer and added to another layer. Removing a mounted child independently throws; detach it first. Sprites outside this layer are unchanged. Physics bodies leave the shared solver and retain their state for basic integration; root constraints and physical animation rigs are disconnected.

Parameters
oldSpriteThe root of the group to remove.
Note
Native callers must retain the host with addRef()/release() to keep it alive after removal. JavaScript handles retain automatically. Removal from a locked physics callback is deferred until the solve ends. Animation modifiers cannot change layer membership.
See also
addSprite(), Part::detachSprite(), removeAllSprites()

◆ serialize()

void serialize ( ISerializer * serializer) const
overridevirtual

Save selected Layer state and its ordered sprites.

Parameters
serializerDestination writer; not null. Select its resource mode before writing. The default ser_Full includes explicit Camera and parallax settings, initial identities, frame artwork, playback, programmed tweens, root and Part PhysicsBody state and active drives. Remaining Layer fade completion delays use seconds. Shared images are written once and use the writer's embedded-resource or external-reference policy.

Camera state requires ser_LayerDraw; ser_Update alone leaves the current camera attachment unchanged. Layer world bounds use ser_Sizes.

Updates with ser_Animations (including ser_Update) transfer sampled local Part transforms, reflection, constant movement and scheduled animations by Part ID. They preserve existing Part identities, parent links and artwork. This includes poses already solved by Part IK. The receiver can stop Layer animations and disable collisions to display only the received state. Part creation/removal, reparenting, artwork changes, IK controller configuration and Part body/constraint state require another initial snapshot; incremental Part records are not full physics checkpoints. A changed Part ID set is rejected.

Independent Parts retain IDs/names, parent links, transforms, tweens and shared Image/Drawing content. Parent links resolve before body publication. Nested Drawing geometry/attributes are embedded; referenced images use the save policy. Rigid mounts retain their mounting Part, child Sprite, sampled child grip frame, error/held pose and nested relationships. Children retain their independent layer draw order. Mount links resolve after all Sprite/Part identities exist; nonphysical and kinematic children retain the same ownership and command restrictions.

Drawing colors and image transparency colors use eight-bit channels, with opaque alpha omitted. Floating-point colors can change by less than one channel step (1/255) when restored. Image pixel data is preserved exactly. Drawing geometry, pixel-space attributes (including thickness, text size, offsets and transform translation), and image subsections use the compact coordinate serializers. These can discard a fractional remainder smaller than 0.001 per encoded coordinate component. Rectangles encode their origin and size, so those small errors can accumulate at the opposite edge. Physics state, collision geometry, constraint anchors, IK inputs and Sprite/Part transforms retain their existing floating-point precision.

Packed boolean flags omit default values and absent payloads. Repeated images, Drawing storage and imported animation assets use shared object references within the same serializer stream. This preserves shared identity and avoids writing the same resource again; independently created objects remain distinct.

Imported SCML animations retain their shared model, selected entity/clip, floating-point playback time, pause/events, character maps, reference pose, bone overrides, blends and interrupted transitions. Bone-, artwork- and socket-bound Parts resolve against the restored rig. Built-in rig IK modifiers and retained Drawing registrations preserve their IDs, options and enabled state. Animation colliders continue following the restored pose.

Complete saves embed the imported document and its images and can load without the source files. Embedded XML is compressed losslessly with zlib when that makes it smaller; decompression is automatic. Documents are limited to 64 MiB before compression, and corrupt payloads or mismatched lengths cause a load error. External-reference saves omit the XML, resolve the original document path and verify that its contents have not changed; images use the selected resource policy. Missing or changed dependencies cause a load error.

Initial records preserve Collider shapes and shape IDs, frame/animation-source options, material overrides, collision filters, sensor/enabled state and contact-event opt-in. Compound-body associations, all PhysicsConstraint types, linked IK limits and active physical Part IK controllers resolve after all owners exist. Captured IK offsets and sampled drives survive; offsets are not recaptured from a deformed pose. Geometry is stored in both resource modes; frame images follow the resource policy. Restored colliders receive new process-wide IDs.

Callback collision filters/handlers are rejected; reinstall application handlers after loading. Solver contact caches and pending contact events are not saved, so loading rebuilds contacts and can produce new Begin events. A resumed simulation is not guaranteed to be bit-for-bit identical to an uninterrupted one.

Note
Initial saves support frame-based and imported Sprite collections with Parts, colliders, constraints, physical Part IK and rigid mounts. Active imported physical rigs, older attachSprite() associations, modifier/drawing callbacks, custom easing/helpers, Font attributes, custom Drawing implementations and links to other layers are rejected. Drawing content requires a GUI-capable build. Port assignment, event handlers and shared-world gravity and damping configuration belong to the receiving application. Discard the writer after a save error.
