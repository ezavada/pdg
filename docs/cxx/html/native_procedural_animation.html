Procedural jiggle and FABRIK

Use AnimationJiggle and AnimationFABRIK with Sprite's enabled animation pose, or with an independent contiguous Part chain. The numeric solvers solveAnimationJiggle(), stepJiggleTarget() and solveAnimationFABRIK() also work on AnimationPose values without a Sprite. Springs use simulation seconds, frequency in Hz, radians for angles and world engine units for displacement/acceleration.

For chain jiggle, AnimationJiggle::chain includes the root bone. Native Part setJiggle() instead accepts following Parts separately; the receiver is the root. Set a positive length for terminal independent Parts. AnimationJiggle::joints provides sparse overrides identified by bone ID (stable Part ID for Part adapters). Unspecified overrides inherit the controller's values. Native settings setters accept a complete configuration; edit the value returned by get*JiggleOptions() to preserve existing tuning. JavaScript setters accept sparse patches. Defaults and numeric ranges are declared by AnimationJiggle and validated by validateAnimationJiggle().

IK-target jiggle requires an existing two-bone controller, identified by AnimationJiggle::ik for Sprite. Filtering happens in world coordinates before the IK solve. The stored desired target is unchanged. Physical Part IK drives accept these filtered targets and continue to resolve contact through their existing bodies and colliders. Chain jiggle does not create bodies or query obstacles.

FABRIK changes joint rotations, preserves offsets and endpoint orientation, and returns AnimationFABRIKResult. At most maxIterations passes run, including for unreachable targets. Sprite limits intersect with live Bone rotation limits. Part solvers use live setIKLimits(). Part parent frames and local scales must be uniform and nonsingular. Invalid configurations throw before editing output.

Modifiers run by stage, order, then registration. IK-target jiggle is a decorator; chain jiggle is post-constraint. Built-in controllers reject competing ownership of the same rotating joints. Springs keep numerical state separate from the animated base, so repeated evaluation does not compound the effect. Reading state or pose advances no simulation. Disabled springs freeze and reenabling reseeds. set*Influence() can fade linearly in simulation seconds.

Full Sprite/Layer snapshots preserve native controllers, state, fades and Part base rotations. Incremental records require unchanged topology. JiggleState restores numerical state only; use full serialization to transfer configuration and animated base motion together.

Native example
pdg::AnimationJiggle settings;
settings.mode = pdg::jiggleMode_Chain;
settings.length = 12;
settings.frequency = 2;
settings.dampingRatio = 0.3;
root->setJiggle(settings, {middle, tip});
root->kickJiggle(2, 0, 1); // Add 2 radians/second to middle.
