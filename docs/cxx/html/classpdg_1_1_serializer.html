Detailed Description

A container for static methods that do the actual serialization.

Note
API Stability: 3 — Stable. This public contract is established. Compatible changes are expected; intentional breaking changes require an announced breaking release and migration guidance. See API stability.

API stability does not promise a fixed snapshot byte format; see API stability.

◆ setResourceMode()

ISerializer & setResourceMode ( int mode)
overridevirtual

Choose whether saved image resources are embedded or externally referenced.

Select embedded resources or permit external resource identifiers. Defaults to serialization_Complete. Set before sizing/writing objects. Runtime resources without an identifier are embedded in either mode.

Parameters
modeserialization_Complete (the default) embeds pixels; serialization_ExternalReferences permits named file/resource references.
Returns
This writer. An invalid constant throws without changing the policy.

The policy belongs to this writer and does not change other writers. Set it before writing data. Serializer rejects a policy change after its first write. Each image record identifies its representation, so readers need no matching setting. Anonymous runtime images and images changed through setTransparentColor() or mutable getData() access are embedded in either mode. ImageStrip frame layout, opacity, edge clamping and subsection/frame views are preserved. Shared source images remain shared when written with serialize_obj(). Initial Sprite frame records use the same policy for artwork and collision masks. Resource policy does not change the serialization flags that select which object state to save.

External identifiers use the original file: path or res: resource name. The reader resolves them through the filesystem or ResourceManager; missing sources and changed dimensions throw an error identifying the resource. Complete records load independently of their original files and resource cache.

Note
Runtime-created and modified images retain their pixels. Named images may reload pixels while saving a complete record; call Image::retainData() before drawing if the original resource will become unavailable before the save. A complete save fails explicitly if pixels cannot be recovered. It never substitutes an external reference. Discard a writer after a failed serialization operation.
Serializer writer;
writer.setResourceMode(serialization_Complete);
writer.serialize_obj(image); // an existing Image*; bytes belong to writer
// For a smaller save that resolves named assets on load, select
// serialization_ExternalReferences before writing to a new Serializer.

◆ sizeof_obj()

virtual uint32 sizeof_obj ( const ISerializable * obj)
overridevirtual

How many bytes are used to serialize a particular object, including tags and size data.

Since objects are only serialized once, it is critical that you call this on objects the same order that you actually serialize those object. The first call for a particular object will return the number of bytes for the serialized object stream plus tag overhead. Successive calls will return the number of bytes used to store a reference to the object, usually a much smaller number A NULL object pointer will always take a constant number of bytes needed for the null object tag
