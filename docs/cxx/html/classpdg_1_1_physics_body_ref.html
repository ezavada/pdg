Detailed Description

template<class Owner>
class pdg::PhysicsBodyRef< Owner >

Read-only Sprite/Part reference property sharing PhysicsBody::NoPhysics until assigned.

This stores only a body pointer, never physical state. Only the owner can change the association through setupPhysicsBody()/removePhysicsBody(). Convert to PhysicsBody& and call addRef() to retain a body independently of its owner; balance it with release(). The property itself always follows its owner.

PhysicsForceId applyForce ( const Vector & force,
double durationSeconds,
double delaySeconds = 0 )
inline

Apply a force for a finite duration.

Force integrates over time; it does not change velocity immediately. Use the point overload to add torque around the center of mass. The point overload takes worldPoint before durationSeconds.

Loads on an active Sprite rig
Finite and continuous forces/torques on sprite.physics act on the selected physical root. The coordinating Sprite stays Kinematic and adds no simulated mass. A new registration requires a Dynamic root; otherwise it returns zero. Driven roots count as Dynamic, and these loads coexist with their controller.

The Sprite owns the returned IDs. Root reassignment or detachment routes existing loads to the replacement root; cancel them through the same sprite.physics. Component registrations use independent IDs and are not cancelled by clearing Sprite loads. Delays and durations advance once per physics step. While the selected root is Kinematic, existing loads age without exerting force and resume if it becomes Dynamic. Snapshots preserve IDs and remaining durations. Loads surviving rig disable continue on a Dynamic single body; a Kinematic/Static handoff clears them.

An off-center force captures its lever arm relative to the selected root at submission. World force vectors and signed torques keep their world coordinates across a Sprite flip. They are not reflected with the rig's pose and velocity.

Parameters
forceFinite force vector in owning-layer axes, in mass times distance per second squared.
durationSecondsFinite nonnegative active duration in seconds; zero applies no force.
delaySecondsFinite nonnegative delay before the force begins, in seconds.
Returns
A nonzero force ID for removeForce(), or pdg::physicsForce_None (0) for zero duration or a non-Dynamic recipient/absent body. An assembly uses its selected root as recipient.
Example
auto& body = sprite->setupPhysicsBody(2, 4);
auto id = body.applyForce(pdg::Vector(0, 8), pdg::Point(110, 50), 0.25, 0.1);

◆ getAngularMomentum()

template<class Owner>
double getAngularMomentum ( ) const
inline

Assembly momentum includes spin and orbital motion about its center of mass.

Read rotational momentum.

For an active Sprite rig, sum component spin and orbital momentum about the assembly center of mass: sum(I_i * omega_i + m_i * cross(r_i - COM, v_i - VCOM)). This includes attached Kinematic bodies, excludes the coordinating body and unregistered/detached parts, and does not assume all parts rotate together.

Returns
Signed clockwise angular momentum in mass times distance squared per second. For a single body, moment of inertia multiplied by angular velocity.
See also

◆ getMomentOfInertia()

template<class Owner>
double getMomentOfInertia ( ) const
inline

Assembly inertia is the instantaneous sum about its center of mass.

Read the body's moment of inertia.

For an active Sprite rig, return the instantaneous inertia about its center of mass: sum(I_i + m_i * distanceSquared(r_i, COM)). This is the inertia the current pose would have if locked rigidly; it changes as articulated parts move. It counts exactly the same attached components as getMass(), including Kinematic bodies. The coordinating body's saved single-body inertia is not included.

Returns
The current moment of inertia in mass times distance squared. Returns zero for NoPhysics.

◆ setBreakAngularSpeed()

template<class Owner>
PhysicsBody & setBreakAngularSpeed ( double radiansPerSecond,
PhysicsBody * referenceBody = nullptr )
inline

Notify when absolute (or reference-relative) angular speed exceeds this limit; zero disables.

Notify when a body exceeds an angular-speed threshold.

The threshold is a notification condition, not a speed clamp. It does not apply braking, disconnect constraints, or split artwork. Existing motor and force-break behavior is unchanged. Both basic and Chipmunk solvers support it, including kinematic bodies and bodies without a collider or joint.

A positive-duration physics step compares the magnitude of the solved angular velocity against the threshold. Equality does not trigger an event. One event is sent per excursion above the limit; a later sampled speed at or below the limit rearms it. Sampling occurs after each world step (before restoring temporary Chipmunk kinematic sweep velocities), or after step() for a detached basic body. It does not detect peaks between those samples. Setters and zero-duration steps never dispatch events synchronously.

Changing the threshold or reference rearms monitoring. Repeating the same settings preserves the notification state. Invalid edits throw without changing settings or rearming. Zero disables monitoring and clears the reference. NoPhysics ignores this operation and always reports zero.

With a reference, speed means abs(body.angularVelocity - referenceBody.angularVelocity); otherwise it means abs(body.angularVelocity). The reference must be a different present body in the same SpriteLayer, or both bodies must be outside a layer. The association is weak: removing its body from its owner or destroying it disables dependent monitors. A world mismatch detected at sampling also disables the monitor. A detached body retains its absolute threshold; relative monitoring is cleared on detachment.

Sprite bodies emit eventType_SpriteBreak on their Sprite; Part bodies emit it on the owning Sprite with the Part identified. Returning false leaves the body and joints unchanged. Snapshots preserve settings and the notification latch. Relative references require a Sprite/Layer graph containing both bodies; external references are rejected. Event handlers are not saved.

Parameters
radiansPerSecondFinite nonnegative magnitude in radians/second. Default body setting is zero (disabled).
referenceBodyOptional borrowed reference body; nullptr selects absolute speed.
Returns
This PhysicsBody, for chaining.
Note
The example assumes Sprite objects named sprite and housing in the same layer.
Example

Drive a dynamic body toward a position and orientation using bounded force and torque.

Installs or replaces an active spring/damper target. The operation preserves the current position and velocity. Each physics step adds a drive contribution to other applied loads; collisions and constraints still determine the solved pose. Repeated successful manual setDriveTarget() calls replace the same manual target; the last call wins. Invalid updates preserve the previous target. A blocked or force-limited body may never reach its target. The drive stays enabled until clearDrive(), stopAllForces(), or a change to kinematic/static mode.

maxForceFinite nonnegative limit on the magnitude of the linear drive force, in mass units times distance units per second squared. Zero disables translation actuation.
maxTorqueFinite nonnegative angular drive torque limit, in inertia units times radians per second squared. Zero disables angular actuation.
frequencyFinite positive response frequency in cycles per second; default 4. Larger values request faster correction, subject to the force limits.
