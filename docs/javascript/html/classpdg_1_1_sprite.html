Detailed Description

animated, moving image that is automatically moved, animated, and drawn

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

Events

Things that happen to a sprite that might require intervention, such as collisions, completed animations, going offscreen, etc... will generate events. Events generated by sprites first go to any handlers attached directly to the Sprite, then propagate up to the SpriteLayer and then the EventManager until they are handled.

Warning
translating events to JavaScript and running them through numerous handlers is expensive. Try to put your handlers as early in the propagation chain as possible.

Inverse kinematics

Use addAnimationIK() to register a two-bone constraint on a supported animation rig. Update its target with setAnimationIKTarget() and inspect the latest solve with getAnimationIKResult(). The returned constraint ID is a pose modifier ID; use removeAnimationModifier() to remove the constraint.

Helpers

You can add helper functions or classes to do specialized animation behavior, and add visual effects during drawing.

See also
setAnimationHelper()
setDrawHelper()
setPostDrawHelper()

◆ activateSubEntity()

activateSubEntity ( string entityName,
string animationName = "idle" )

activates a sub-entity with the specified name and animation

This function activates a sub-entity within the Spriter animation system. Sub-entities are additional animated components that can be controlled independently of the main Spriter animation.

Parameters
entityNameThe name of the sub-entity to activate
animationNameThe name of the animation to play on the sub-entity

Sub-entities are typically used in complex character animations where different parts of the character (like arms, legs, or accessories) need to be animated independently. Each sub-entity can have its own set of animations and can be controlled separately from the main sprite.

When a sub-entity is activated, it will start playing the specified animation. The sub-entity will continue playing until it's deactivated or another animation is specified.

Warning
If the entityName or animationName is invalid, the function will fail silently
Note
Sub-entities are only available for sprites that support them (typically Spriter animations)
The sub-entity will be positioned relative to the main sprite's position and rotation
Returns
true if the sub-entity was successfully activated, false otherwise
See also
Sprite::deactivateSubEntity()
Sprite::isSubEntityActive()

◆ addAnimationDrawable() [1/2]

uint addAnimationDrawable ( Drawing drawing,
object options )

attach an editable Drawing to an animation bone

Use this overload to attach artwork, such as a weapon or a marker, that follows a bone as the sprite animates. Create the artwork with pdg.createDrawing() and the ordinary Drawing methods, such as Drawing.addRect() or Drawing.addImage(). The drawing uses coordinates relative to the selected bone; PDG positions, rotates, and scales it with the bone's final animation pose.

Parameters
drawingThe Drawing to attach. Its contents remain editable after registration, including through ElementRef objects returned by its methods.
optionsAn object selecting the bone, placement, and optional drawing settings. See Drawing options below.
Returns
A nonzero unsigned integer identifying the registration. Pass this ID to setAnimationDrawableEnabled(), removeAnimationDrawable(), or getAnimationDrawableError().
Note
Call enableAnimationPose() successfully before registering artwork. The sprite's animations must have a fixed hierarchy: their active bones and bindings, and their parent relationships, must remain consistent across clips.
Example: attach a marker to a hand
This example assumes sprite is a Spriter sprite in a visible layer, with a reference animation and a bone named hand. Use the clip and bone names from your own artwork.
if (!sprite.enableAnimationPose('reference')) {
throw new Error(sprite.getAnimationRigError());
}
const artwork = pdg.createDrawing();
const marker = artwork.addRect(
new pdg.Rect(-3, -3, 3, 3),
new pdg.Attributes().fillColor('yellow')
);
const drawableId = sprite.addAnimationDrawable(artwork, {
bone: 'hand',
placement: pdg.animationDraw_AfterAll
});
// A later edit appears on the next draw; no new registration is needed.
marker.setAttributes(new pdg.Attributes().fillColor('cyan'));
// When the marker is no longer needed:
// sprite.removeAnimationDrawable(drawableId);

Drawing options (both overloads)
Both overloads accept the following options fields. Only bone is always required. Use the numeric pdg constants for placement and stroke space; strings such as "afterAll" or "local" are not accepted.
Field Type Default Meaning
bone string or integer Required Bone name or zero-based bone ID. See getAnimationBoneNames().
placement integer pdg.animationDraw_AfterAll Where to draw relative to the sprite's authored images; see the placement table below.
slot string Empty string Image binding name. Required for slot placements; omit it for pdg.animationDraw_BeforeAll and pdg.animationDraw_AfterAll. See getAnimationBindingNames().
order integer 0 Lower values draw first within the same placement and slot. Equal values preserve registration order.
strokeSpace integer pdg.animationStroke_PortPixels How line thickness responds to scale; see Stroke thickness below.
bounds object Omitted Rectangle with finite numeric left, top, right, and bottom fields in bone coordinates. Must include all artwork and stroke extents.

◆ serialize()

serialize ( Serializer serializer)

Write selected Sprite state to a data stream.

Parameters
serializerDestination writer. A Sprite in a layer uses SpriteLayer::setSerializationFlags(); an off-layer Sprite uses pdg.ser_Full. Initial frame records include images, collision masks, frame layout and the fractional playback cursor when the corresponding animation and image flags are selected. Shared images retain their identity within the record. Serializer::setResourceMode() chooses embedded pixels or external image references. Programmed transforms/tweens and PhysicsBody state, including active drives, are included by the matching state flags. Timing values use floating-point seconds.

Updates with ser_Animations (including ser_Update) transfer sampled local Part transforms, reflection, constant movement and scheduled animations by Part ID. They preserve existing Part identities, parent links and artwork. This includes poses already solved by Part IK. The receiver can stop Layer animations and disable collisions to display only the received state. Part creation/removal, reparenting, artwork changes, IK controller configuration and Part body/constraint state require another initial snapshot; incremental Part records are not full physics checkpoints. A changed Part ID set is rejected.

Initial records also preserve independent Parts: IDs/names, parent links, local transforms, paused/active tweens, bodies and active drives. Part Image/Drawing content retains geometry, attributes, nested drawings and shared images. Drawing content is embedded in both modes; its images follow the selected resource policy.

Drawing colors and image transparency colors use eight-bit channels, with opaque alpha omitted. Floating-point colors can change by less than one channel step (1/255) when restored. Image pixel data is preserved exactly. Drawing geometry, pixel-space attributes (including thickness, text size, offsets and transform translation), and image subsections use the compact coordinate serializers. These can discard a fractional remainder smaller than 0.001 per encoded coordinate component. Rectangles encode their origin and size, so those small errors can accumulate at the opposite edge. Physics state, collision geometry, constraint anchors, IK inputs and Sprite/Part transforms retain their existing floating-point precision.

Packed boolean flags omit default values and absent payloads. Repeated images, Drawing storage and imported animation assets use shared object references within the same serializer stream. This preserves shared identity and avoids writing the same resource again; independently created objects remain distinct.

Imported SCML animations retain their shared model, selected entity/clip, floating-point playback time, pause/events, character maps, reference pose, bone overrides, blends and interrupted transitions. Bone-, artwork- and socket-bound Parts resolve against the restored rig. Built-in rig IK modifiers and retained Drawing registrations preserve their IDs, options and enabled state. Animation colliders continue following the restored pose.

Complete saves embed the imported document and its images and can load without the source files. Embedded XML is compressed losslessly with zlib when that makes it smaller; decompression is automatic. Documents are limited to 64 MiB before compression, and corrupt payloads or mismatched lengths cause a load error. External-reference saves omit the XML, resolve the original document path and verify that its contents have not changed; images use the selected resource policy. Missing or changed dependencies cause a load error.

Initial records preserve Collider shapes and shape IDs, frame/animation-source options, material overrides, collision filters, sensor/enabled state and contact-event opt-in. Compound-body associations, all PhysicsConstraint types, linked IK limits and active physical Part IK controllers resolve after all owners exist. Captured IK offsets and sampled drives survive; offsets are not recaptured from a deformed pose. Geometry is stored in both resource modes; frame images follow the resource policy. Restored colliders receive new process-wide IDs. Body angular-speed break thresholds, reference identities and notification latches also survive. Relative references must belong to the saved graph; a reported excursion does not repeat on restore. Native PhysicsBody break callbacks must be cleared before saving.

Initial records also preserve active physical rigs created from explicit configurations or generated skeletons. They save edited body/collider/constraint components, bone mappings, root selection, attached/detached membership, aggregate mass, desired poses, Kinematic/Dynamic/Driven modes, manual drive targets, rig drive settings and recovery progress. A pending recovery or disable resumes with its remaining duration and completion notification; a completed recovery is not reported again. Load into a Chipmunk-capable build and use a physics-enabled layer to continue simulation. A standalone restored Sprite can be inspected before adding it to a layer. These records preserve engine state, not application callbacks; re-register application logic after loading. Save at an unlocked physics boundary. Select animation control for a physical rig or its bones.

Kinematic follows the desired animation/IK pose using swept bodies. Dynamic releases rig tracking and lets physics determine the pose. Driven keeps dynamic bodies and applies bounded tracking forces and torques. Mixed is query-only. Changing control preserves body, collider and joint identities, mass, velocities and independent scheduled loads. Kinematic-to-kinematic joints remain configured but dormant. A single selected body can still be restrained by its neighbors.

Selections use the skeleton hierarchy, including skipped bones. An included bone may be selected alone; a skipped bone may select included descendants. Missing bones or selections with no physical bodies throw. The entire selection is validated before any control changes. Driven requires configured drive settings on every selected body.

A body has one controller. Before rig tracking takes over, release a manual drive with PhysicsBody::clearDrive(), or release a physical Part IK chain with Part::clearIKTarget(). To release rig tracking, select Dynamic. Raw clearDrive() and manual setDriveTarget() cannot replace rig-owned control. Repeated manual setDriveTarget() calls are allowed after release: the last valid call wins. Direct mapped-body physics.setMode() uses the same coordinator: Dynamic releases rig tracking, Kinematic requests default recovery, and Static throws.

Driven limbs track their desired transform relative to the nearest included physical ancestor. Reaction forces and torques act on dynamic parents; free limbs are not independently pinned to world coordinates. Bodies without an included ancestor track an animation root target in world coordinates. Solver-followed Sprite translation does not move that target. Rotations use physical body frames, including the reflected reference pose. Resolved angular routes persist across ticks; AsSpecified preserves unwrapped turns. Physical joint limits remain binding.

Positive recoveryTime blends the requested target from the current physical pose. During recovery, the affected bodies remain dynamic and getAnimationPhysicsMode() reports Driven, including when the destination is Kinematic. The requested time is a minimum transition duration: completion waits until position error is within 0.1% of segment length (at least 0.000001 layer units) and angular error is within 0.001 radians. Contacts, joint limits or insufficient force may delay completion indefinitely. PhysicsBody::getDriveState() reports the target and actual error; normal collision events report contacts. There are no recovery-start or blocked events. Pausing animation does not pause physical recovery.

Recovery uses bounded integral correction to remove steady gravity/load error, within the same force and torque caps. Recovery uses stored drive settings if available. For an unconfigured transition to Kinematic only, a temporary 4 Hz, critically damped servo uses force capped at mass * max(segment length, 0.001) * (2*pi*4)^2 and torque capped at inertia * (2*pi*4)^2. This does not configure the persistent drive-settings record. Configure settings explicitly to tune those bounds. Zero recoveryTime takes control immediately; Kinematic moves to the requested pose, while Driven starts its bounded drive immediately. Dynamic release is always immediate.

There are no automatically inferred angular limits or drives.

Repeated setup requires the original membership (all generated Parts, no added accessories); edited membership must first be restored. It reapplies the original mass fractions, scaling inertia proportionally while keeping bodies, colliders, joints, edited geometry, velocity and independent loads. Changing unitsPerMeter or switching from an explicit definition requires disableAnimationPhysics() first. Ordinary physics.setMass() preserves the current, possibly tuned, mass fractions instead. An existing bone-named Part must have the same binding/offset, no parent, unit unreflected local scale, and no body or collider. Conflicts throw before replacing caller-owned associations. Mapped offsets/bindings and Part removal remain fixed until disabled. Change body control with setAnimationPhysicsMode(). Edit physical properties and geometry through the Part's physics/collider objects; changing geometry does not recalculate inertia.

The Sprite's physics.getMass() reports component mass; physics.setMass() scales all component masses and inertia atomically. Individual mass edits change the total without redistributing. Whole-Sprite linear/angular impulses target the selected root, including the world-point lever arm. Velocities, continuous forces/torques and manual drives should be applied to the component bodies. Single-body setupPhysicsBody(mass, inertia) and aggregate setMomentOfInertia() reject while this rig is active. Inertia/angular-momentum queries on the Sprite still describe its coordinating body, not a pose-dependent assembly sum.

Parameters
totalMassFinite positive mass in application mass units.
unitsPerMeterFinite positive number of layer distance units per meter; default 1 means meter coordinates for the fallback conversion. For example, 1000 makes the 1 mm fallback one layer unit. Other authored dimensions are already in layer/rig units and are not converted by this argument.
Returns
This Sprite, for chaining.
Note
Requires an enabled animation pose, Chipmunk support and a physics-enabled SpriteLayer. Configure the layer before adding Sprites. Bone scales must be nonsingular; nonuniform authored bone scales and reflected initial poses are supported. The Sprite root needs uniform scale. Set Sprite scale/flip before setup: dynamic physical bones keep their initial effective scales while enabled. Call outside pose modifiers and locked solver callbacks. Initial Sprite/Layer snapshots preserve active rigs, edited components, membership and control/recovery state. The example assumes a bone named forearm and successful pose setup.

sprite.findPart('forearm').physics.setMass(3); // changes the total
sprite.physics.setMass(80); // scales the current distribution

◆ transferPart()

Part transferPart ( Part part,
boolean includeDescendants = true )

Transfer an existing Part and optional subtree into this Sprite.

Moves the same Part objects; retained Part, PhysicsBody, Collider and internal PhysicsConstraint handles remain valid. Names and Part-owned Image/Drawing content are retained. The destination assigns fresh per-Sprite IDs and appends the moved Parts in their source order. Read getId() again after transfer. Transferring a Part already owned by this Sprite is a no-op.

World transforms, body mass/inertia, velocities, loads, manual world-space drives and collision settings are preserved. The moved root loses its old Part parent; parents inside the transferred set are retained. With includeDescendants false, children left behind keep their world placement and nearest remaining Part ancestor. Movement, rotation and scale programming is canceled on Parts whose parent frame changes. Logical size animation and other local state remain.

Descendants include ordinary Part children, physical-rig bone descendants and registered assembly children. Joints within the selected set survive. Joints to any body outside it disconnect; retained handles report inactive. Source assembly mass decreases by the transferred member masses without redistributing the others. The destination does not automatically register the transferred bodies in its rig: use attachAnimationPhysicsPart() and create any new joints explicitly.

Mapped rig bodies are released from the source controller and become ordinary Dynamic Part bodies. At least one attached skeletal body must remain in the source rig; transferring its selected root chooses a remaining root using the usual rule. Source bone/artwork/socket bindings are cleared rather than rebound by name. The source skeleton, animation clips, imported artwork and animation-drawing registrations remain source-owned; use Part.setDrawing()/setImage() for artwork that moves with the Part. The source rig can subsequently be disabled or destroyed without removing the transferred bodies. Layer snapshots preserve the resulting ownership and joints.

Parameters
partPart currently owned by a Sprite.
includeDescendantsTransfer descendants too; optional, default true.
Returns
The same Part, now owned by this Sprite.
Note
Both Sprites must share a layer, or both be off-layer. Names must be unique in the destination. Singular/sheared placements that cannot be represented by Part transforms and Sprite-mount cycles reject before transfer. Call outside animation modifiers, drawing callbacks and locked physics callbacks. Finish or cancel source rig recovery first. Clear any Part IK target involving a selected Part; re-establish it after transfer. Release manual drives before detaching attached skeletal bodies, following the existing explicit drive-handoff contract. Independent or already detached bodies retain their manual drives. Parent-relative IK limits are cleared when their frame changes. The example assumes a physical weight Part and a hand in the receiving Sprite's active rig.
Example
const weight = receiver.transferPart(donor.findPart('weight'));
