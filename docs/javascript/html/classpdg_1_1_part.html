Detailed Description

An independently animated part owned by a Sprite.

Independently animated Sprite subsection, artwork holder, or mounting frame.

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

Create a Part by calling createPart() on a Sprite instance. Part cannot be constructed directly with new.

const sprite = new pdg.Sprite();
const part = sprite.createPart("hand");
part.moveTo(new pdg.Point(12, 0), 0.25, pdg.easeInOutQuad);

Part inherits Animated's programmed movement, rotation and size operations. All animation durations are floating-point seconds. The owning Sprite advances its attached Parts; do not also call animate() on an attached Part every frame.

Bone binding is optional. getBoneId() is safe on an unbound Part and returns pdg.boneId_None. Binding and hierarchy belong to Part, not Animated. Part has an optional PhysicsBody through its physics property. setupPhysicsBody() creates it explicitly; otherwise physics returns pdg.PhysicsBody.NoPhysics. Only setupPhysicsBody()/removePhysicsBody() can change the property association. Compare physics with pdg.PhysicsBody.NoPhysics to test absence. Removing a Part detaches its body and stops automatic stepping.

A retained Part remains valid after removal from its Sprite; isAttached() reports false and its independent local transform remains available.

Create a Part with Sprite::createPart(name); names are unique within that Sprite. Its local transform is relative to the Sprite, an explicit parent Part, or an authored bone, binding or socket. setParentPart(), bindToBone(), bindToAnimationBinding() and bindToAnimationSocket() select one frame without changing local offsets. getBoneId() is always safe and returns boneId_None for an unbound Part (including one whose parent follows a bone). Authored relationships are scoped to the current rig and safely invalidate on replacement.

setDrawing() retains shared editable Drawing contents. setImage(image,localBounds) retains an image in an explicit local rectangle. Artwork changes leave identity, logical dimensions, programmed motion, parent/binding and physics untouched. clearContent() removes artwork. getContentBounds() returns current artwork-local bounds or transformed bounds in partSpace_Sprite/partSpace_World. Part content is drawn after the owner's existing artwork, in Part creation order, with the owner's opacity and composed affine transform. Imported bindings supply transforms; this API does not duplicate or automatically replace imported artwork. Drawing still copies Attributes for its individual elements.

Attaching an independent Sprite

hostPart.attachSprite(child, placement, childMount) returns a new Part beneath hostPart. This mounting Part retains the child and supplies an Animated attachment offset; getAttachedSprite() and child.getAttachmentPart() query the relationship. Animate the mounting Part to move the held object. The child root rejects competing transform edits, while its own clips, internal Parts, opacity and layer order remain independent. Attachment neither merges Part ownership nor steps the child twice.

partPlacement_Snap aligns the child's origin, or the optional childMount frame, with the host. partPlacement_PreserveWorld keeps its current world placement. childMount must belong to the child; its frame is sampled once when attaching. The mount's local state is the only editable attachment offset. detachSprite() releases the child with its last published world pose and leaves the mounting Part available for reuse as an ordinary Part. Removal of the host socket or owning Sprite also detaches. Layer removal currently detaches mounts because placement and update scheduling require a shared layer. JavaScript references retain Parts and Sprites automatically.

Both Sprites must share a layer (or both be outside layers). Cycles, an already mounted child, singular placement, or a root transform requiring shear are rejected before creating a mount. Independent Part artwork supports affine shear, but Sprite roots do not. A later invalid follow placement holds the last valid child pose and reports getAttachmentError(); valid placement clears it. Use uniform ancestor scales or aligned axes when rotating mounts. Rigid attachments currently require a child without a PhysicsBody; physical holding constraints are not supported by this attachment API. Release does not invent physical velocity.

const socket = hero.createPart("weaponGrip");
socket.bindToAnimationSocket("grip");
const held = socket.attachSprite(sword, pdg.partPlacement_Snap);
held.rotateTo(0.3, 0.25, pdg.easeInOutQuad);
held.detachSprite();

Explicit Part-chain IK

solveIK(middle,tip,target,space,bendDirection,influence) solves two segments whose joint offsets come from the local locations of a contiguous three-Part chain. It requires neither artwork nor bones. The target defaults to owning-layer/world coordinates; partSpace_Local means the root Part's parent frame. The root's local scale must have equal absolute axes; ancestor transforms may be affine/reflected. The bend direction is +1 or -1, and influence is in [0,1]. Unreachable targets clamp to the available reach and return false. Invalid topology or dynamic bodies reject the operation before changing either joint. Direct IK replaces rotation programming; setIKTarget() and setIKDriveTarget() install recurring controllers, and setIKLimits() supplies fixed or shared rotary limits. Controller takeover requires explicit release with clearIKTarget().

Part bodies

An unbound Part can create its own PhysicsBody without a Sprite root body. It joins the Chipmunk world on a physics-enabled layer and publishes the solved state once; removal detaches the retained body back to basic integration. This currently covers free bodies, shared constraints, contact reporting and kinematic target scheduling. Use setupCollider() for explicit geometry, setupFrameCollider() for owned artwork or an explicitly selected image binding, and setupAnimationCollider(boxName) for one authored box. Bone binding alone does not create a physical joint or give the body authority to write a bone. Generated animation physics requires Chipmunk.

Mount an independent Sprite on this Part.

Creates a new child Part beneath this host. The returned mounting Part controls the attachment offset; animate it rather than the child Sprite's root. The child's clips, internal Parts, opacity, and layer order remain independent. Existing root motion/tweens and physical velocity are canceled when attaching. A mounted kinematic body follows the same target; direct body teleport, velocity edits, and changes out of kinematic mode throw until detachment. In a Chipmunk layer, the target is evaluated before the solve and its sweep velocity participates in contacts.

Parameters
childSprite to retain and mount. It must share the host's layer (or both must be outside layers), have no PhysicsBody or a body in physicsBody_Kinematic mode, and not already be attached.
placementpdg.partPlacement_Snap aligns origins; pdg.partPlacement_PreserveWorld preserves the child's current world placement.
childMountOptional Part belonging to the child. Its frame is sampled once as the child's mounting point instead of its origin.
Returns
A new mounting Part owned by the host's Sprite.
Note
To mount a physical Sprite, create its body and set physicsBody_Kinematic before attaching. Cycles, singular transforms, and child-root transforms requiring shear are rejected before creating a mount. Removing the host from its layer removes the whole mounted group while preserving the mounts. Adding the host to another layer carries its descendants; detach a child before moving it independently. Layer coordinates are preserved during transfer. Use uniform ancestor scale or aligned axes when rotating attachments.
See also
detachSprite(), getAttachedSprite(), getAttachmentError(), Sprite::getAttachmentPart()

◆ setIKDriveTarget()

Part setIKDriveTarget ( Part middle,
Part tip,
Point target,
number maxForce,
number maxTorque,
int space = partSpace_World,
int bendDirection = 1,
number influence = 1,
number frequency = 4,
number dampingRatio = 1 )

Drive a two-segment Part chain toward an IK target using bounded forces and torques.

Installs a persistent controller. Each step computes a desired pose after Part animation and before the physics solve. The solver retains authority over all physical positions and rotations; registering or updating a target does not teleport the chain. The root and middle must have independent dynamic bodies. The tip may have a dynamic body or no body. All three Parts must form a contiguous chain in one Sprite. Imported physical-rig Parts are not supported by this controller.

The first assignment captures the root's parent-relative anchor and the middle and tip joint offsets. Repeated assignments to the same chain retain those values, so physical drift cannot redefine segment lengths. Clear and reinstall to capture a new chain configuration. Ancestor movement and the current Part scales still apply. The root requires uniform absolute scale, as with solveIK().

The controller owns each participating body drive until clearIKTarget(). Existing independent body drives or overlapping IK controllers cause setup to throw without replacing the old controller. Direct setDriveTarget(), clearDrive(), stopAllForces() and changes away from dynamic mode reject while the controller owns the body. Impulses and other forces may still disturb it. No joints are created implicitly: configure pivot joints, physical angular limits and collision shapes separately. Any pivot or pin between adjacent driven Parts must join the captured parent offset to the child origin (pin distance zero). Mismatched anchors reject setup or suspend a running controller. Anchors are unscaled body-local coordinates; account for Part scaling when configuring them.

The root's target position is its captured anchor; the middle and physical tip receive the solved joint positions. Body orientations use the shortest rotation route, except joints sharing a rotary limit preserve its unwrapped relative angle so the drive does not request a shortcut through the physical stop. Force/torque caps apply separately to each body. A physical tip retains its captured local orientation relative to the desired middle pose. Influence zero turns off the controller's drive contribution without releasing ownership.

A missing/replaced body or invalid topology stops all this controller's drives and records getIKError(). Valid topology can resume; after replacing a body, call setIKDriveTarget() again to claim it. isIKTargetReached() measures the current physical endpoint, so a constrained or force-limited chain may remain unreached without a configuration error. Clearing preserves velocities, constraints and independently applied loads.

Parameters
middleThis Part's immediate child, with a dynamic PhysicsBody.
tipMiddle's immediate child, with a dynamic body or no body.
targetDesired endpoint in the selected coordinate space.
maxForceFinite nonnegative force cap per driven body.
maxTorqueFinite nonnegative torque cap per driven body.
spacepartSpace_World by default; partSpace_Sprite or partSpace_Local (root's parent frame) are also accepted.
bendDirection+1 by default, or -1 for the other bend direction.
influencePose influence from zero through one; default 1.
frequencyPositive drive frequency in cycles per second; default 4.
dampingRatioNonnegative drive damping ratio; default 1.
Returns
This Part for chaining.
Note
Advance the owning SpriteLayer normally. Bodies use either the basic or Chipmunk solver; step size, constraints and force caps affect convergence. Initial Sprite/Layer snapshots preserve the controller, captured joint offsets, body drives and shared rotary limits in either resource mode. Save the containing Layer when a joint or compound collider references another Sprite. Restored controllers retain exclusive ownership of their bodies and resume on the next step.

number maxAngle )

Limit this joint's local rotation when solving Part IK.

Angles are radians in the Part's parent frame. Both bounds must be finite, representable as Part rotations, and ordered, spanning at most one full turn. Equal bounds lock the desired angle. Maintain a target for a contiguous two-segment Part chain.

Registers or replaces this root's controller without changing the current pose. During a Sprite step, all Parts advance their local animation and callbacks first; controllers then run in parent-before-child order, followed by physical publication. tipDirect child of middle, in the same Sprite.
targetFinite target position in the selected space.
spaceInteger pdg.partSpace_Local, pdg.partSpace_Sprite, or pdg.partSpace_World constant. World coordinates belong to the owning layer. For this solver, Local means this root Part's parent frame.
bendDirectionInteger +1 or -1 selecting the elbow side.
influenceFinite blend amount from 0 (unchanged) to 1 (full solve).
Returns
True when the resulting tip reaches the target within tolerance; false when it cannot, including partial influence.
Note
All three Parts must share a Sprite and form a direct chain. The root scale must be nonzero with equal absolute axes. Zero-length segments, singular parent frames, and dynamic bodies are rejected before changing either joint.
Example
const root = sprite.createPart('armRoot');
const middle = sprite.createPart('elbow');
const tip = sprite.createPart('handTip');
middle.setParentPart(root).setLocation(new pdg.Point(10, 0));
tip.setParentPart(middle).setLocation(new pdg.Point(8, 0));
root.solveIK(middle, tip, new pdg.Point(12, 8), pdg.partSpace_Sprite);

◆ unbindFromBone()

Part unbindFromBone ( )

Clear authored frame bindings.

Clears direct bone, animation-binding, and socket associations. Keeps any explicit parent Part. Nonphysical and kinematic Parts keep their local transform; dynamic and static bodies keep their world position and rotation, recalculating the local transform in the remaining frame.

Returns
This object, for chaining.
