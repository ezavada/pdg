Detailed Description

Animated view owned by a Port or shared by layers.

Scene-owned cameras advance on their scene clock. Layer overrides remain available; Scene describes ownership and pause behavior.

See Camera visibility, fades and transitions for camera visibility, composed opacity, fades and crossfades.

Camera inherits EventEmitter event handling and Animated movement, rotation, scale, reflection, pivots, helpers, timed chains and schedule controls. Moving its location right moves visible world content left. Rotation uses radians and is inverted in the view; zoom and scale magnify content. Camera size is animation metadata and does not resize a viewport. For a Port-owned camera, location + centerOffset maps to the Port anchor, in port coordinates. Anchors default to (0,0). An explicit layer camera maps its focus to the center of its stored viewport.

A layer's explicit camera overrides its Scene camera and port camera. Clearing the explicit camera restores inheritance from its Scene, or from the current Port for a legacy layer. Every Port owns its camera. Attachments retain cameras; getCamera()/getEffectiveCamera() preserve shared JavaScript identity. Attached cameras advance once per runtime tick regardless of attachment count or whether a layer is paused or hidden. Scene-owned cameras advance on scene time and stop when their scene pauses. animate(seconds) additionally advances state, and is intended for manual/detached animation.

Direct Port Renderer drawing applies the camera once outside local Attributes transforms, including nested Drawings. Layers project sprites, Parts, particles and tiles through their effective camera once. Port clipping and clear operations remain in port coordinates. MVC Views automatically draw in screen space. For direct screen drawing, disable camera drawing temporarily and restore it in finally. Port conversions still use the camera while drawing is disabled.

Note
Port attachment and rendering require a graphics-capable build. Camera animation and explicit layer attachments also work headlessly. Camera zoom must stay finite and positive, and its view must have finite, nonzero scale.
const camera = port.getCamera();
port.setCameraAnchor(new pdg.Point(320, 240));
const actors = pdg.createSpriteLayer(port);
const background = pdg.createSpriteLayer(port);
background.setCameraParallax(0.5, 0);
camera.setLocation(100, 200).zoomTo(2, 0.5, pdg.linearTween);
// Both layers inherit camera; background ignores zoom and scrolls half as far.

◆ cutTo()

Camera cutTo ( Camera destination)

Schedule an atomic camera visibility and picking handoff.

Hide this camera and show the destination at the scheduled instant, without a blended frame. Position, zoom, opacity, animation and following remain unchanged. The cut is immediate unless delayed by wait() or placed after an operation using andThen(). A paused schedule delays execution; cancellation before execution leaves both cameras' visibility unchanged. Cancelling after execution does not undo the cut.

Parameters
destinationA distinct output Camera. It may use another viewport or Port, or be unattached; cuts also work in headless builds. Effects-stage cameras cannot participate.
Returns
This camera for chaining.
Note
A pending cut retains the destination and reserves both cameras against other handoffs. Pending cuts cannot be serialized, repeated, reversed or replayed with restartIt(); request a new cut after completion or cancellation. Removing either camera's last attachment cancels a pending cut. Unlike blended transitions, cuts do not require contiguous scene pairs or matching viewports.
Example
source.wait(0.5).cutTo(destination);

◆ lumaFadeTo()

Camera lumaFadeTo ( Camera destination,
number seconds,
Image mask = null,
number softness = 0.1,
boolean darkFirst = false,
int easing = easeInOutQuad )

Reveal a live destination using a frozen luminance mask.

Note
Parameter easing: EasingFunction.

The mask stretches to the common viewport using nearest sampling. Luminance is computed from straight RGB in linear color space; fully transparent pixels have zero luminance. The mask is frozen at the first rendered transition frame, while both scene images remain live. Without an explicit mask, that first source-camera image supplies it. Supplied images are retained until completion or cancellation. On resize, the frozen mask stretches to the new viewport. Progress endpoints show the complete source and destination even for uniform black or white masks.

Parameters
destinationDistinct camera attached to the same Port with the same nonempty viewport.
secondsFinite nonnegative duration in seconds.
maskOptional Image, or null to derive the mask from the initial source output.
softnessReveal-band width in linear luminance units, from 0 to 1; defaults to 0.1. Zero gives a hard edge.
darkFirstFalse reveals bright pixels first; true reveals dark pixels first.
easingEasing function; defaults to easeInOutQuad.
Returns
This camera for chaining.
Note
Scene layers must remain contiguous. The source receives picking throughout the transition; completion hides it and shows the destination. Shared transition pause, queue, cancellation and snapshot restrictions apply.
Example
source.lumaFadeTo(destination, 1.0, null, 0.15, false, pdg.linearTween);

◆ matchCutTo()

Camera matchCutTo ( Camera destination,
CameraMatchCutOptions options )

Match two Sprite compositions and preserve apparent motion across a hard cut.

The mode names the reference shot and whether to match size. During the approach, mode: pdg.matchSource preserves the outgoing shot and aligns the hidden incoming camera so matchTarget reaches matchSource's live Port position. mode: pdg.matchTarget eases the outgoing camera so matchSource reaches matchTarget's live Port position. At the cut the engine matches projected bounds centers, apparent velocity and, with an AndSize mode, apparent size and its rate of change. Size means the largest dimension of the projected Sprite bounds; rotation and aspect ratio are preserved.

The source schedule owns the approach and settling phases. Both cameras remain reserved until settling finishes; andThen() starts its successor afterward. Visibility and picking switch at the approach boundary. wait(), pauseSchedule(), resumeSchedule(), cancelSchedule() and stopIt() apply to the whole operation. Cancellation before the cut removes matching adjustments and restores visibility. Cancellation after the cut retains the incoming view at its current framing. Removed/reassigned subjects or detached cameras cancel safely. Pending operations retain the destination, check Sprite lifetimes and cannot be saved as snapshots, repeated, reversed or restarted.

Parameters
destinationIncoming camera, retained until completion or cancellation.
optionsMatching settings described below.
Returns
This source camera for chaining.

Matching options
Field Default Meaning
matchSource Required Sprite belonging to the source camera.
matchTarget Required Distinct Sprite belonging to the destination camera.
mode matchSource Camera matching enum; see the four modes below.
approachSeconds 0.4 Finite positive time to synchronize the scenes before the cut or fade.
settleSeconds 0.4 Finite positive time to ease out inherited camera motion after the cut or fade.
settleReturnsCamera false Retain the matched framing and deceleration travel. Set true to restore the incoming base framing/zoom or its live following view.
approachEasing easeInQuad Registered monotonic easing with zero/one endpoints.
settleEasing easeOutQuad Registered monotonic easing controlling the decay of extra motion.
Mode Behavior
pdg.matchSource Preserve the source shot; align the incoming camera's position and apparent motion without adjusting zoom.
pdg.matchSourceAndSize Match the source shot, also matching apparent size and its rate using zoom.
pdg.matchTarget Move the outgoing camera toward the target shot without adjusting zoom.
pdg.matchTargetAndSize Approach the target shot's position and size; carry apparent motion and size rate through the cut.

Following and independent camera effects continue. Keeping matched framing also retains the resulting following offset. Matching corrections compose with the camera's live base position and zoom; settleReturnsCamera removes those corrections at completion. The matchSource and matchTarget modes leave zoom unchanged. getLocation() and getZoom() expose the base pose while temporary matching corrections are active; layer coordinate conversions include those corrections.

Note
Requires graphics, Sprites on layers sharing a Port and identical nonempty camera viewports. Translation parallax must be nonzero; zoom matching also needs nonzero zoom parallax and nonempty projected bounds. Pixel snapping and view-bounds clamping are unsupported for either matched camera. Use logical Sprite bounds that describe the artwork being matched. Overshooting or reversing easings throw.

◆ matchFadeTo()

Camera matchFadeTo ( Camera destination,
CameraMatchFadeOptions options )

Synchronize two Sprite compositions, crossfade while matched, then settle.

Uses the modes and matching settings in camera_match_options. After the approach synchronizes the scenes, both live scenes crossfade. Their Sprite bounds centers remain aligned throughout the blend; AndSize modes also maintain equal projected bounds size. The outgoing camera carries its approach motion through the fade. At the fade endpoint the destination inherits apparent motion and settles with the same behavior as matchCutTo(). Following, Sprite motion and camera effects continue during all three phases.

The source schedule owns approach, fade and settling. Both cameras remain reserved until settling finishes; andThen() follows all three phases. Picking uses the source during the fade and switches to the destination when fading ends. Pausing freezes the operation. Cancellation during approach or fade restores original visibility and removes matching corrections; cancellation during settling retains the incoming framing.

◆ transitionTo()

Camera transitionTo ( Camera destination,
number seconds,
int style = camera_Crossfade,
int easing = easeInOutQuad )

Transition between two live camera scenes.

Note
Parameter easing: EasingFunction.

For crossfades, the engine interpolates the premultiplied complete scene images, including their own opacity and flash effects. It does not fade individual sprites or independently source-over two weighted scenes. Wipes partition the viewport between the two scene images, retaining full source opacity on the unrevealed side and destination opacity on the revealed side. Both scenes stay live. At completion the source becomes hidden and the destination becomes visible; their opacity values are unchanged. The source receives picking during the transition, and the destination receives it after completion.

Parameters
destinationRetained destination camera rendering into the same Port and viewport.
secondsFinite nonnegative duration in seconds.
stylecamera_Crossfade (default), camera_WipeLeft, camera_WipeRight, camera_WipeUp, camera_WipeDown, camera_LumaFade or camera_WhipLeft/Right/Up/Down. Luma and whip styles use default settings; use lumaFadeTo() or whipPanTo() to customize them.
easingRegistered easing constant. Defaults to easeInOutQuad.
Returns
This camera for chaining.
Note
Keep this camera's layers contiguous in drawing order. Runtime frames own compositing.
Example
// sourceWorld and destinationWorld are layers attached to the same port.
const bounds = port.getDrawingArea();
const source = new pdg.Camera().setViewport(bounds);
const destination = new pdg.Camera().setViewport(bounds).hide();

destinationWorld.setCamera(destination);
source.transitionTo(destination, 0.75, pdg.camera_Crossfade,
pdg.easeInOutQuad);
// To reveal from the bottom instead, choose pdg.camera_WipeUp.
// Runtime frames advance the transition and switch visibility on completion.

◆ whipPanTo()

Camera whipPanTo ( Camera destination,
number seconds,
int style = camera_WhipLeft,
number blur = 0,
int easing = easeInOutQuad )

Slide live camera outputs with optional directional motion blur.

Note
Parameter easing: EasingFunction.

The source slides out and the destination enters from the opposite edge. Offsets belong to composition: persistent camera location, following and parallax are unchanged. Camera opacity remains independent for each scene, and all samples clip to the common viewport. Blur averages eight nearby progress samples, with its spread fading to zero at the endpoints. The reference speed is one viewport per 0.65 seconds: halving the duration doubles blur spread, and doubling the duration halves it. Zero blur uses one sample. Both scenes continue rendering live; at completion the source hides and the destination shows.

Parameters
destinationDistinct camera attached to the same Port with the same nonempty viewport.
secondsFinite nonnegative duration in seconds.
stylecamera_WhipLeft (default), camera_WhipRight, camera_WhipUp or camera_WhipDown; names describe source travel.
blurStrength from 0 to 1, default 0. At the reference duration of 0.65 seconds, maximum sample spread is 15 percent of the viewport extent times this strength. Spread scales by 0.65 / seconds and is capped at one viewport extent for very fast pans.
easingEasing function; defaults to easeInOutQuad.
Returns
This camera for chaining.
Note
The source receives picking until completion. Shared transition ordering, pause, cancellation and snapshot restrictions apply.
Example
source.whipPanTo(destination, 0.4, pdg.camera_WhipLeft, 0.7);
