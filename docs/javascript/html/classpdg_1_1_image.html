Detailed Description

A bitmap image that can be blitted onto the screen.

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

You can create an image from a file or an offscreen Port, or load it from resource files with the ResourceManager.

const img = new pdg.Image("myImage.png");
// Given an offscreen Port named surface:
const live = new pdg.Image(surface, pdg.SharedSurface);

◆ Image() [2/2]

Image ( Port port,
boolean copyPixels = CopyPixels )

Create an independent snapshot or a live image of an offscreen surface.

Parameters
portAn open Port returned by GraphicsManager::createOffscreenPort().
copyPixelsDefaults to pdg.CopyPixels (true): copy the current RGBA pixels into an independent image. With pdg.SharedSurface (false), retain the shared drawing surface: subsequent Port drawing is visible the next time the image is drawn, without constructing another image or uploading pixels when both use the same graphics context. Literal booleans remain supported; an omitted or undefined flag uses CopyPixels.

Creates an Image with the port's dimensions and transparency. Throws an Error for an onscreen port and TypeError for a non-boolean copyPixels. Use new with this constructor.

Both kinds of image remain usable after the source port closes. Closing a port with live images prevents further drawing through that port but retains its final surface until the last live image is released. Closing the underlying graphics context preserves its final pixels for surviving images. Drawing does not depend on which clip rectangle was active when the image was created: the image always represents the whole surface.

Pixel reads and serialization of live images read the current contents. Serialized images are snapshots and do not restore a connection to a Port. Drawing across independent graphics contexts, or drawing a live image back into its own source, uses a pixel snapshot. Calling setTransparentColor() on a live image converts that image to an independent snapshot before applying the color key.

Note
Requires a graphics-enabled build. Shared images retain graphics memory until released, even after closeGraphicsPort(). An image's opacity is independent of the port.
API stability: 2 — Evolving.
Example
const surface = pdg.gfx.createOffscreenPort(new pdg.Rect(128, 128));
if (!surface) throw new Error('Could not allocate drawing surface');
const live = new pdg.Image(surface, pdg.SharedSurface);
surface.drawEllipse(new pdg.Point(64, 64), 40, 40,
new pdg.Attributes().fillColor('red').lineStyle(pdg.lineStyle_None));
// Drawing live now shows the red circle; further surface drawing updates it too.
const frozen = new pdg.Image(surface, pdg.CopyPixels);
// frozen keeps this circle even when the surface changes.

◆ getAlphaValue() [1/2]

number getAlphaValue ( int x,
int y )

get the value for the alpha channel at the given x, y coordinates in the image

The alpha channel is the transparency of the image. An alpha channel value of 0 is completely transparent, 255 is completely opaque. If the image does not have an alpha channel, then it will return the overall image opacity, as if you had called getOpacity() * 255.

Parameters
xthe x coordinate of the point in the image to get the data from
ythe y coordinate of the point in the image to get the data from
Returns
alpha channel value from 0..255
Note
When an image is first drawn into a port, the image is data is converted into an OpenGL texture and the original image data is purged. Once that happens getAlphaValue() will no longer work. If you need to access the image's alpha channel even after drawing it, use retainAlpha() to prevent the alpha channel from being purged.

retain alpha data for use by Image.getAlphaValue() or per-pixel sprite collisions

◆ setEdgeClamping()

setEdgeClamping ( boolean inUseEdgeClamp)

set whether image uses edge clamping or not

Deprecated
Edge clamping should be on for images except when they are used as repeating textures. In a forthcoming release the drawing engine will automatically do the right thing with edge clamping, and this function will be removed from the image API.

Edge Clamping is useful for applications where you want a single copy of the texture to appear on a large surface. It makes the edges on a large surface align more cleanly with the edges of the image. You should turn off edge clamping with images you intend to use as repeating textures, such as with calls to Port.drawTexture() or Port.drawTexturedSphere().

Fig. 1: Edge Clamping

In the example above you can see faint diagonal white lines on the left hand image (no edge clamping). Those lines are not present in the right hand image after edge clamping is turned on.

Parameters
inUseEdgeClamptrue to use it, false to not
Note
Edge Clamping is on by default for images, so you shouldn't need to change this setting in most cases.

◆ setOpacity()

setOpacity ( number opacity)

set opacity of this image

Opacity can be used on an Image regardless of whether it has an alpha channel or not. In images with an alpha channel, the transparency of any given pixel is that pixel's alpha channel value * the image opacity (0.0 .. 1.0).

Parameters
