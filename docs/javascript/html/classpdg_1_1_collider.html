Detailed Description

Optional shapes, filtering, sensors and contacts for a Sprite, Part or Particle.

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

Use Sprite::setupCollider(), Part::setupCollider() or Particle::setupCollider(). Their read-only collider property returns the same handle until removeCollider(); beforehand it returns shared Collider::NoCollider. Collider is independent of animation, artwork and physical motion. Creating one never creates a PhysicsBody.

Local circles, capsules, rectangles and polygons follow their owner's affine transform, including parent/bone motion, scale and reflection. Nonuniformly scaled or sheared circles and capsules use convex approximations; see collider_capsule_geometry. Singular geometry does not participate in the collision world. getBounds(), contains() and overlaps() are explicit geometric queries and ignore event filters.

Enable SpriteLayer::enableCollisions() for contacts within a layer, or SpriteLayer::enableCollisionsWithLayer() for a linked pair of layers. Connected PhysicsBodies suppress their mutual contacts unless each connecting constraint allows them. Multiple shapes on the same body do not collide with one another. Contacts between linked layers using different solvers use basic impulse response.

A solid collider uses its owner's body by default. Without a body it acts as an externally positioned, immovable surface with no simulated velocity. Use a kinematic PhysicsBody for a moving platform that must carry or push objects. setPhysicsBody() explicitly contributes a Part's geometry to a compound body; useOwnerPhysics() restores the default association. Sensors report overlaps without impulses and work without any physical body.

Note
Both Sprite and Part owners advance automatically. Native contact callbacks and opted-in eventType_ColliderContact events run after solving. Callbacks can remove colliders, bodies, owners or layers; contact payloads describe the solved frame, so another callback may already have detached a referenced collider.
const layer = pdg.createSpriteLayer();
layer.enableCollisions();
const sprite = layer.createSprite();
const foot = sprite.createPart('foot');
foot.setupPhysicsBody(1, 10);
foot.setupCollider().setCircle(8).setWantsContactEvents(true);
sprite.addHandler(new pdg.IEventHandler(function(event) {
if (event.phase === pdg.collision_Begin && event.collider === foot.collider) {
console.log('Foot contacted shape ' + event.otherShape);
}
return true;
}), pdg.eventType_ColliderContact);

Retained handles remain queryable after removal, using the final transform; callbacks and physical associations are cleared. Initial Sprite/Layer snapshots preserve collider geometry/configuration, compound body links and constraints. Use a Layer snapshot for links between Sprites. Callback filters and contact handlers cannot be saved; reinstall them after loading. Native callers can also use independent Collider and CollisionWorld objects for custom owner types.

See also
PhysicsBody, PhysicsConstraint, ColliderContact

Geometry sources and explicit additions
Operation Frame/animation source Caller-added shapes
Sprite.setupFrameCollider / setupAnimationCollider Selects the source and follows subsequent artwork updates Clears previous geometry when selecting the source
addCircle / addCapsule / addBox / addPolygon / addImageMask Continues updating Adds a persistent shape in owner-local coordinates
removeShape Throws for a source-controlled ID Removes that addition only
setCircle / setCapsule / setBox / setPolygon / setImageMask Stops following artwork Replaces all geometry with the supplied shape
clearShapes Stops following artwork Removes all geometry

Source updates preserve IDs by frame or authored box name. Source IDs may be inactive while an animation box is absent, and return when the box reappears. getShapeCount()/getShapeId() enumerate the currently present shapes. getShapeName() returns the authored box name, "frame" for a frame source, or an empty string for an explicit shape. Contacts aggregate convex pieces under each public shape ID.

◆ setCapsule()

Collider setCapsule ( Point start,
Point end,
number radius )

Replace all geometry with one capsule.

The capsule consists of the line segment between start and end, expanded by radius in every direction. Endpoints are the centers of the rounded ends in owner-local coordinates. Total length is the distance between the endpoints plus twice the radius, and width is twice the radius. Coincident endpoints behave as a circle while retaining collisionShape_Capsule as the public type.

Coordinates are copied. Validation finishes before existing shapes are replaced; the capsule receives a fresh shape ID. This stops any frame/animation geometry source, while preserving collider settings, owner/body association, mass and inertia. NoCollider ignores the operation.

Queries and both solvers use exact capsule geometry under translation, rotation, reflection and uniform scale. Nonuniform scale or shear uses a convex outline with 16 straight segments per semicircle plus the two straight sides; coincident endpoints use the same 32-sided approximation as a deformed circle. All pieces remain one public shape ID. Capsule geometry and IDs survive scene snapshots; older readers without capsule support reject that shape kind.

Parameters
startFinite local center of the first cap.
endFinite local center of the second cap; may equal start.
radiusFinite positive radius in owner-local distance units.
Returns
This Collider, for chaining.
Note
Available in both GUI and headless builds; artwork is not required.
Example
const sprite = new pdg.Sprite();
sprite.setupPhysicsBody(2, 30);
sprite.setupCollider().setCapsule(new pdg.Point(-12, 0), new pdg.Point(12, 0), 3);
const shape = sprite.collider.getShapeId(0);
const start = sprite.collider.getCapsuleStart(shape);

The example creates a capsule 30 units long and 6 units wide. Add the Sprite to an active collision-enabled layer to simulate contacts.

See also
addCapsule(), getCapsuleStart(), getCapsuleEnd(), getCapsuleRadius(), setCircle()
