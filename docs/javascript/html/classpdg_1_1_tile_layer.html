Detailed Description

efficiently handles large tile datasets, useful for backgrounds, terrains, etc...

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

Capabilities

Each TileLayer has a tile set, a set of equal size tiles taken from a single image. There can be at most 256 tiles in an image.

Tile sets can contain transparency, either through a transparent color or via an alpha channel. If a tile set does not contain transparency, then the entire tile world will be filled in solid, there is no way to leave out a tile. In tile sets with transparency, tile type 0 is considered empty, even if the there is no transparency in the actual image.

Tile sets can support tile rotation (facing) or tile flipping (vertical, horizontal, or both). You cannot use both rotation and flipping in the same layer.

Tile rendering uses the effective Camera, including rotation, zoom, nonuniform scale and reflection.

Getting the Results you Want

For truly impressive maps, you will rarely use just a single TileLayer. Because TileLayers are highly optimized for large areas of transparent/empty tiles, you can use a number of linked TileLayers that each focus on different details: water, terrain, ground cover, flowers and shrubs, trees, etc...

You can intersperse regular SpriteLayers in between TileLayers to provided animated effects to make your characters move at the right layer (underneath the tree-tops, for example).

Attach a shared Camera to the destination Port or individual layers. Layers inherit their port camera unless explicitly overridden; SpriteLayer.setCameraParallax() can give backgrounds different motion.

◆ defineTileSet()

defineTileSet ( int tileWidth,
int tileHeight,
Image tiles,
boolean hasTransparency = true,
boolean flipTiles = false )

define image and dimensions for the tiles used by this layer

Each TileLayer has a set of equal size tiles taken from a single image. The tileWidth and tileHeight specify the size of each individual tile in the image, and the image should divide evenly into tiles with no left-over space. There can be at most 256 tiles in an image.

Tile sets can contain transparency, either through a transparent color or via an alpha channel (See Image for more details on transparency).

Tile sets can support tile rotation (facing) or tile flipping (vertical, horizontal, or both). You cannot use both rotation and flipping in the same layer.

To support rotation, you must have a maximum of 64 tiles in your tile set. Typically the tiles would be arranged in an 8x8 grid, with the top left corner tile being considered tile 0 and then counting left to right, top to bottom.

To support flipping in both directions, your tile set should be laid out just like for rotation, 64 tiles in an 8x8 grid. For horizontal flipping only, you should have 128 tiles in an 8x16 grid, and for vertical flipping only you should have 128 tile in a 16x8 grid. For all kinds of flipping you must pass true for the flipTiles parameter when you call defineTileSet().

Extract a rectangular region of tile data from the layer.

This function extracts a rectangular region of tile data from the TileLayer and returns it as a MemBlock containing the tile indices.

Parameters
mapWidthThe width of the region to extract in tiles. Defaults to the layer's current world width.
mapHeightThe height of the region to extract in tiles. Defaults to the layer's current world height.
srcXThe X coordinate of the top-left corner of the region to extract. Defaults to zero.
srcYThe Y coordinate of the top-left corner of the region to extract. Defaults to zero.

The function returns a MemBlock containing tile indices arranged in row-major order (left to right, top to bottom). Each byte in the returned data represents a tile index from the specified region.

The extracted data can be used with TileLayer::loadMapData() to copy tile data between layers or save it for later use.

Returns
A MemBlock containing the tile indices from the specified region
Exceptions
RangeErrorIf the requested width or height, including the source offset, exceeds the layer's world dimensions.
Note
The returned data format is compatible with TileLayer::loadMapData(Uint8Array, int, int, int, int)

int mapWidth = 0,

Load tile data from a MemBlock into the specified region of the layer.

This function loads tile data from a MemBlock into a specific rectangular region of the TileLayer. The data is interpreted as a 2D array of tile indices.

Parameters
dataThe MemBlock containing the tile data to load
mapWidthThe width of the tile map in the data (number of tiles horizontally)
mapHeightThe height of the tile map in the data (number of tiles vertically)
dstXThe X coordinate where to place the top-left corner of the loaded data in the layer
dstYThe Y coordinate where to place the top-left corner of the loaded data in the layer

The MemBlock data should contain tile indices arranged in row-major order (left to right, top to bottom). Each tile index corresponds to a tile in the TileLayer's tile set.

The function will load the specified rectangular region from the data into the layer starting at the destination coordinates (dstX, dstY).

Warning
The function will overwrite existing tile data in the destination region
If the data size doesn't match mapWidth * mapHeight, the behavior is undefined
Note
Tile indices in the data should be valid for the layer's tile set
