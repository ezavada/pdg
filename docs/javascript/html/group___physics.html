Detailed Description

Things used for handling physics simulation.

PhysicsBody controls motion, forces and material properties; Collider supplies collision geometry and contact events, and PhysicsConstraint connects bodies. Sprites and Parts share these APIs.

Note
Animation physics requires Chipmunk in C++ and JavaScript. The Basic solver supports simple shared PhysicsBody/PhysicsConstraint use; it is not an animation-rig backend and will not be expanded to support complex animation physics. Use supportsAnimationPhysics() to check build capability and enable Chipmunk on the SpriteLayer before setupAnimationPhysics() or setupPhysicsFromAnimationRig(). Ordinary authored playback and pose IK do not require physics.

Basic and Chipmunk solver comparison

Compare the native solvers using the same physical inputs. Step time measures CPU cost; overlap, joint error and settling describe the resulting physical behavior. The measurements below apply to the native engine used by both language APIs; they do not measure JavaScript binding or callback overhead.

Latest measurements with all implemented improvements, 2,000 dynamic bodies and colliders per test. Stack and pile tests add static supports; chains add static anchors.

The approach grid varies vertical offset by row and first-contact time from 10 to 1 seconds by column. Both solvers hit all 830 intended pairs and avoid all 170 misses, with at most 0.01 seconds of contact-time error. The touching grid varies force direction from inward to vertical and magnitude from 0.5 to 8; both solvers release 995 pairs and keep the five head-on pairs under force.

Small timing differences in the single-run tests should not be treated as conclusive. Measured 2026-09-22.

Enable Collider::setWantsContactEvents() on each collider whose owner should receive notifications. Both Sprite and Part colliders deliver through the owning Sprite. Each receiving collider sees itself as collider; vectors reverse for the other endpoint. Delivery occurs synchronously after the solve.

Contact fields
Field Meaning
emitter Owning Sprite receiving this event
eventType pdg::eventType_ColliderContact
collider, other Shared Collider handles identifying both endpoints
shape, otherShape Stable shape IDs within the corresponding colliders
phase collision_Begin, collision_Stay or collision_End
point Approximate contact Point in owning-layer/world coordinates
normal Unit Vector directed from collider toward other
impulse Actual impulse applied to other; zero for sensors, sleeping contacts and end contacts
penetration Nonnegative overlap depth; zero for an end contact
sensor Whether either collider is a sensor

Chipmunk contacts reuse its solved manifold: point is the mean of the contact midpoints and penetration is the greatest overlap depth. Sleeping pairs continue to report collision_Stay without a new impulse.

Geometry, filters and physical associations are evaluated for the solved frame. A callback can remove an endpoint before another notification is delivered; retained handles remain safe and isAttached() reports their current state. Contact identity is per shape pair, so compound geometry can generate several notifications for the same two owners. Native ColliderContact pointers are borrowed only for the callback; JavaScript retains its Collider handles.

Register an IEventHandler for eventType_SpriteBreak on the owning Sprite. Part body notifications use their owning Sprite's route. Inspect reason to distinguish the two event forms. Body notifications work with both basic and Chipmunk solvers.

Break event fields
Field Meaning
emitter, eventType Standard event emitter and eventType_SpriteBreak.

reason physicsBreak_AngularSpeed or physicsBreak_Force.

targetSprite, joint Legacy joint endpoint and CpConstraint; null for speed events.
impulse, force, breakForce Legacy joint impulse, solved force and break threshold; zero for speed events.

Angular-speed notifications do not clamp speed, apply braking, disconnect joints or split artwork, regardless of the handler's return value. They fire once per sampled excursion above the limit; returning to or below the limit rearms them. See PhysicsBody.setBreakAngularSpeed() for sampling and reference lifetime rules.

Legacy Chipmunk joint-force events retain their existing behavior: returning true handles the notification; an unhandled event invokes the existing disconnect path. Shared PhysicsConstraint force breaking retains its existing behavior too; this body feature does not add force events to that separate constraint path.

◆ pdg::SpriteCollideEvent

struct pdg::SpriteCollideEvent

a Sprite collided with something (Optional)

This event reports Sprite layer-wall notifications and imported physical-rig contacts. Shared Collider contacts use eventType_ColliderContact and Collider.setContactHandler(), with stable collider and shape identities. 

{
    emitter: {},            // the emitter that generated this event
    eventType: 20,          // the event type (eventType_SpriteCollide)
    action: 0,              // what happened (action_CollideSprite or action_CollideWall)
    actingSprite: {},       // the moving Sprite
    inLayer: {},            // the SpriteLayer that contains the Sprite
    targetSprite: {},       // the Sprite that was collided with (for action_CollideSprite)
    normal: {               // the normal vector for the collision
      x: 1.0,
      y: 0.0
    },
    impulse: {              // the impulse imparted by the collision
      x: 29.35,
      y: 0.883
    },
    force: 384.0,           // the force of the collision
    kineticEnergy:883,      // the total kinetic energy of the collision

    arbiter: {},            // the Chipmunk Collision Arbiter (*Chipmunk Physics Only*)

    collisionName: "box1",      // name of collision box that was hit (null for non-spriter)
    withCollisionName: "box2",  // name of other sprite's collision box (null for non-spriter)
    isFirstContact: true        // true if this is the first contact in a collision sequence
}
Note
Enable layer collisions with SpriteLayer.enableCollisions(). Use Collider.setContactHandler() for ordinary Sprite and Part contacts.
