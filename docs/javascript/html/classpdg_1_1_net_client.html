Detailed Description

a network endpoint that can initiate a connection

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

NetClient is part of the PDG Engine's custom protocol for games. It handles protocol negotiation and optional connections. It establishes both a TCP connection (reliable transport with guaranteed delivery) and UDP communications (small and unreliable but fast) with the server.

On iOS JavaScriptCore, NetClient connects to existing PDG TCP/UDP servers using host and port. hasNetwork and hasNetworkClient are true; hasNetworkServer is false and NetServer is unavailable. UDP uses the TCP local endpoint; sendDgram() uses TCP until UDP negotiation succeeds, when UDP becomes unavailable, or for serialized messages larger than 1492 bytes. Pass {noDatagram: true} to the constructor to disable UDP.

Callbacks run on the engine's JavaScript thread. Entering the background closes connections and reports ERR_NETWORK_BACKGROUND through onError(); onClose() runs when the engine resumes. Reconnect explicitly when the application becomes active. No automatic reconnect occurs. Native TCP/UDP is unencrypted; NetConnection.secure is false for native transport. iOS also supports WebSocket: pass webSocketUrl or transportPolicy: "websocket-only" to connect to a PDG WebSocket listener. WSS uses the iOS certificate trust store and reports secure as true; ws:// requires secure: false. Custom tls options are unsupported on iOS. WebSocket sendDgram() uses reliable delivery and hasDgram remains false. The server must allow clients without a browser Origin header.

Desktop, Node and iOS also support WebTransport. Supply webTransportUrl and transportPolicy:"webtransport-required" to require its TLS reliable stream and optional datagrams. Browser auto mode attempts WebTransport before WebSocket. See websocket_client_options for deadlines, fallback and certificate hashes.

Note
Apps connecting to a server on the local network must supply an NSLocalNetworkUsageDescription in their Info.plist. The OS controls permission.

NetClient doesn't actually handle network communication, it only establishes the connection. Once established, it creates NetConnection objects you can use to send and receive data.

Warning
NetClient, NetServer, and NetConnection all work together over a custom protocol. Do not attempt to use NetClient to connect to other kinds of servers, such as HTTP or raw TCP sockets. There are perfectly fine Net and HTTP modules built-in to Node.js (and thus to PDG) for that.

NetClient connect ( NetServerAddress serverInfo,
function callback,
string clientKey = "" )

connect to a server for your game

Connect to a PDG server and complete its authentication and version handshake.

Note
Parameter callback: NetConnectCallback.

The callback receives one NetConnection after the handshake completes. Errors go to onError(). WebSocket and WebTransport connections carry the same serialized messages as native TCP. sendDgram() uses reliable delivery on WebSocket. Authentication failures close the attempt; they never start another connection automatically.

Parameters
serverInfoConnection settings in websocket_client_options.
callbackFunction receiving the established NetConnection.
clientKeyOptional reservation key sent before protocol negotiation.
Returns
This NetClient for chaining.

Client connection options
Field Default Meaning
host, port Required for native TCP Native server hostname and port. For WebSocket, host may be used to derive the URL.
transportPolicy "auto" Desktop, Node and iOS preserve TCP unless a web URL is supplied. Browsers try WebTransport, then WebSocket. An explicit webTransportUrl selects WebTransport in native auto mode. "webtransport-required" forbids fallback; "websocket-only" selects WebSocket; "native-only" rejects browser use.
webSocketUrl Derived Explicit wss:// URL. Native auto mode selects WebSocket when only this web URL is supplied. Browser auto mode derives its initial HTTPS WebTransport URL from this URL when webTransportUrl is omitted.
webTransportUrl Derived HTTPS WebTransport URL. Derived from host, webPort and webPath, or the browser webSocketUrl. Requires an HTTP/3 WebTransport listener.
serverCertificateHashes Omitted Optional array of {algorithm:"sha-256", value:Uint8Array or ArrayBuffer} entries, each containing a 32-byte SHA-256 DER certificate digest from a trusted bootstrap. Requires a currently valid EC certificate with validity no longer than 14 days. These hashes authenticate the server certificate; the PDG client key still authenticates the client.
webTransportTimeout 1500 Milliseconds allocated to the initial WebTransport attempt in auto mode, within the overall timeout.
capabilityCacheTimeout 30000 Milliseconds to cache an unsupported or timed-out WebTransport endpoint. 0 disables caching. The cache is bounded and keyed by endpoint and trust configuration.
webPort, webPath 5443, "/pdg" Derived endpoint is wss://host:webPort/webPath.
secure true false permits an explicit ws:// development endpoint. HTTPS pages always require wss://.
timeout 5000 for web transports and iOS Overall connection and PDG handshake deadline in milliseconds for web transports. On desktop/Node TCP, applies only when supplied.
handshakeTimeout timeout or 5000 PDG handshake deadline in milliseconds; web transports also respect the remaining overall timeout.
maxFrameSize 1048576 Maximum reliable payload size in bytes.
maxPendingBytes 4194304 Maximum retained input and pending transport output bytes. WebSocket output overflow reports ERR_BACKPRESSURE; WebTransport overflow reports ERR_BACKPRESSURE; iOS TCP/WebSocket overflow reports ERR_NETWORK_BACKPRESSURE. iOS accepts 1024 to 67108864 bytes and also bounds queued events and writes to 256 each.
tls Platform defaults Native WebSocket client TLS settings, such as ca for a private certificate authority. WebTransport uses the platform trust store on Apple/Windows and the system CA bundle on Linux, or native tls.caFile for a private CA. Browser TLS uses platform trust. iOS WebSocket rejects custom tls options.
Note
The server must permit the page's origin and offer the pdg-net-v1 WebSocket subprotocol. Production endpoints need a trusted certificate and a proxy that forwards WebSocket upgrades. WebTransport requires UDP access to the HTTPS endpoint port. WebSocket uses TCP. Native WebTransport clients have no browser Origin; permit the empty string in the listener allowedOrigins.

Auto mode falls back only for unavailable WebTransport, an explicitly unsupported endpoint, or establishment timeout, before the PDG handshake begins. Certificate, pin, authentication, and protocol failures are terminal. Browsers often report opaque failures; these are terminal rather than treated as unsupported. No fallback occurs after a transport has been selected or a session has connected.

Example
const client = new pdg.NetClient();
client.onError(error => console.error(error.code, error.message));
client.connect({webSocketUrl: "wss://game.example.com/pdg"}, connection => {
connection.onMessage((message, connection, delivery) => {
console.log(message, delivery, connection.transport);
});
connection.send({join: "lobby"});
}, "reservation-key");

Member Data Documentation

◆ connection

object connection

reference to the NetConnection, or boolean false if not yet connected

JavaScript value
NetConnection or false.

The property starts as the literal false. After the underlying socket connects, it holds a NetConnection. It is not a general boolean flag, and assigning a connection does not by itself mean the PDG protocol handshake has completed. Use the connect callback to know when the connection is ready for application messages.

Note
A retained connection object is not proof that its socket is still open. Use the connection callbacks to track disconnection and errors.
