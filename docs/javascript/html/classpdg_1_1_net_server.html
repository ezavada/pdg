Detailed Description

a network endpoint that can accept incoming connections

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

Overview

NetServer is part of the PDG Engine's custom protocol for games. It handles protocol negotiation and optional connections. It provide a server that listens for connections with a client over both TCP (reliable transport with guaranteed delivery) and UDP (small and unreliable but fast).

NetServer doesn't actually handle network communication, it only listens for incoming connections. Once a connection is established, it creates a NetConnection object for each connected client that you can use to send and receive data.

In cases where your server consists of multiple processes (most game servers do, especially ones that expect to scale to handle a large number of users) a particular server process may be both a server and a client. For example, it might accept connections from players over the internet using a NetServer, but then connect (using a NetClient) to a central message distribution system to relay chat between players connected to different server nodes.

Authorization & Reservations

There are 5 different ways you can allow clients to connect:

  1. Wide Open - clients do not require any authorization or reservation to connect. Obviously this is the least secure, but is fine for server processes that are all behind a firewall, or peer to peer connections. This is the default setting for NetServer if no options are used.
  2. Common Key - clients all send the same static key. To do this, call expectClient() once with the static key and no other parameters. That will allow all clients to call NetClient.connect() with that static key. Attempts to connect without the key will be rejected by the NetServer
  3. Computed Key - clients and server each compute a key based on some common information that they all have, most likely the UTC date/time. This is nearly the same as a static key, except that the single key doesn't last forever. To do this, all expectClient() with the new key at a regular interval and set a reservationTTL for the keys. Make sure you pass "*" (any ip) for the clientIPAddr. You will probably want the TTL to be slightly longer than the new key interval to give clients a little extra time to connect with the previous computed key, to allow for differences in date/time between different systems.
  4. Per-Client reservation - Each client gets a unique key for their exclusive use during a session, set on the server side by calling expectClient(). Generally this happens when the user logs in. This is made stronger if the client's IP address is also part of the reservation. The reservation should have a time to live (TTL).
  5. Single Use Reservation - This is by far the most secure, especially when combined with IP address checking. Any time the client is going to connect to a server, it must be given a key, and the server must be told to expect that key using expectClient(). TTL should be short (10s of seconds) and the singleUse flag should be passed as true to expectClient().
Warning
NetClient, NetServer, and NetConnection all work together over a custom protocol. NetServer doesn't handle raw TCP nor any other protocol such as HTTP. There are perfectly fine Net and HTTP modules built-in to Node.js (and thus to PDG) for that.

NetServer ( NetServerOptions opts = null)

Configure native and optional WebSocket/WebTransport listeners for a standalone server.

NetServer is available when pdg.hasNetworkServer is true. Browser and iOS builds expose NetClient and NetConnection and report hasNetworkServer as false.

Parameters
optsOptional settings described below. Construction does not bind ports.

Server options
Field Default Meaning
native true Enable the existing TCP/UDP listener.
serverAddr, serverPort "0.0.0.0", 5000 Native bind address and port. port is an alias for serverPort. Port 0 allocates an available port, reported by ready().
fixedPort false Allow native TCP to retry sequential ports after EADDRINUSE when false.
noDatagram false Disable native UDP and WebTransport datagram use. WebSocket always uses reliable delivery.
reservationRequired false Require an expectClient() reservation and its key.
handshakeTimeout 5000 Milliseconds permitted for an incoming PDG handshake. 0 disables the server handshake timer.
webSocket false true enables a web listener with shared settings. An object overrides port, host, path, secure, tls, allowedOrigins and limits.
webTransport false true or an object enables an HTTP/3 WebTransport listener. The object overrides host, port, path, tls, allowedOrigins and limits.
webPort, webPath 5443, "/pdg" Shared web listener port and path. WebSocket uses TCP and WebTransport uses UDP, so they may share a numeric port. Native TCP and WebSocket require separate nonzero TCP ports.
tls Required for secure WebSocket certFile and keyFile paths, or cert and key values. WebTransport requires certFile and keyFile paths. Certificate changes require restarting the listener.
allowedOrigins [] Exact allowed page origins. Empty rejects all upgrades. Include a native WebSocket client's configured Origin as needed; include "" for native WebTransport clients without an Origin. "*" is development-only.
allowPartialListen false Permit successfully bound listeners to serve when another listener fails. Otherwise startup closes all listeners and ready() rejects.

WebSocket object limits: maxFrameSize (1048576 bytes), maxPendingBytes (4194304 bytes), maxConnections (1024), maxConnectionsPerIP (32), maxConnectionsPerOrigin (1024), maxConnectionsPerMinute (120 per IP), maxIncompleteHandshakes (128), and idleTimeout (30000 milliseconds between ping checks). Clients that miss a pong are disconnected on the next check. Text messages are rejected.

Note
WebSocket uses TLS by default. secure:false explicitly enables ws:// for local development. The certificate's private key belongs only on the server. WebTransport always uses TLS. Its object accepts the same limits as WebSocket, with idleTimeout as the QUIC idle deadline and maxPendingBytes from 1024 to
  1. Admission limits range from 1 to 4096. maxIncompleteHandshakes also limits pending PDG handshakes. listeners reports native, websocket and webtransport addresses separately after ready(). A WebTransport connection reports secure:true and transport:"webtransport". Its confirmed datagram limit is used by sendDgram(); larger payloads use the reliable stream.
Example
const server = new pdg.NetServer({
serverPort: 5000,
webSocket: true,
webTransport: true,
allowedOrigins: ["https://game.example.com"],
tls: {certFile: "certs/server.crt", keyFile: "certs/server.key"}
});
server.onError(error => console.error(error.transport, error.code));
server.listen(connection => {
connection.onMessage(message => connection.send(message));
return true; // Accept the authenticated connection.
});
server.ready().then(addresses => console.log(addresses)).catch(console.error);

number broadcast ( NetworkSendable message,
function filter = null )

send a message to all connections, with optional filter

send a message to all connected clients

Note
Parameter filter: NetAcceptCallback or null.

Go through all the NetConnections in the connections array send the message to each of them. If a filter function is used, instead of sending to all, only send to the ones that filter function returns true for.

The filter function should take one parameter, a Net Connection, and should return true if the connection passes the filter, and false if it is excluded by the filter.

Parameters
messageA string, Uint8Array (including Node Buffer), JSON-compatible object or array, null, MemBlock, or ISerializable. See NetworkSendable. Uint8Array inputs use binary serialization; JSON-compatible objects, arrays and null use JSON serialization. Top-level numbers and booleans are not accepted.
filterthe filter function. If not passed, all connections will be sent the message.
Returns
the number of connections that were actually sent a message

NetServer expectClient ( string clientKey,
string clientIpAddr = '*',
int reservationTTL = FOREVER,
boolean singleUse = false )

make a connection reservation for a client

When a server is created with the reservationRequired flag set to true, the server needs to know how clients are authorized. Use this to make specific reservations for clients by unique key and/or IP address; or a general reservation for all clients using a shared key, perhaps computed based on UTC date and time.

Parameters
clientKey- the key the client(s) must provide
clientIpAddr- the IP address the client is allowed to connect from (defaults to '*', which means any IP address will be accepted)
reservationTTL- how long this reservation is valid (defaults to forever)
singleUse- flag to indicate if the reservation becomes invalid after it is used (default to false, can be used multiple times until expiration)
Returns
itself for call chaining

NetServer listen ( function callback)

Start configured listeners and receive authenticated PDG connections.

Note
Parameter callback: NetAcceptCallback.

Calls callback(connection) after the PDG key and version handshake. Return true to accept the connection; a false return or exception closes it. Native and WebSocket connections use this same callback. Call ready() to observe startup; see websocket_server_options for listener settings and rollback behavior.

◆ ready()

object ready ( )

Wait until the requested listeners are bound.

Returns a Promise resolving to an array of bound listener addresses, including transport, address, port and secure. WebSocket entries also contain path. server.listeners.native and server.listeners.websocket contain these snapshots, or null when unavailable. Call listen() first. With the default atomic startup, a failed listener closes all requested listeners and rejects the Promise. With allowPartialListen, individual failures reach onError() and successfully bound addresses resolve; failure of every listener still rejects.

Returns
Promise of the bound address array.

◆ shutdown()

shutdown ( boolean closeExisting = true,
boolean kill = false )

stop listening for new connections

Stops every requested native and WebSocket listener and cancels incomplete handshakes. server.listeners entries become null. shutdown() may be called repeatedly.

This will also do a clean shutdown of all existing connections made through it, unless you tell it not to by passing false for closeExisting.

To stop receiving incoming connections, but leave existing connections intact, call shutdown(false). The kill parameter is ignored when closeExisting is false.

Parameters
closeExistingflag for whether existing connections should be closed or not (defaults to true if not passed)
killflag for whether existing connections should be killed. True means kill, false means allow to drain normally (defaults to false if not passed).
