Detailed Description

A retained physical relationship between any two PhysicsBody owners.

Note
API Stability: 2 — Evolving. This API is implemented and supported, but its contract is still settling. Compatibility is preserved where practical; breaking changes are documented in release notes. See API stability.

Create through PhysicsBody methods, such as createPinJoint(), createSpring() or createMotor(). The same API joins Sprite-to-Sprite, Sprite-to-Part and Part-to-Part. Shapes are optional. A constraint never changes a Part's parent or bone binding. Do not construct this class directly.

The factory receiver is body A; the other argument is B. Anchor coordinates are local to the physical body, without artwork scaling. Relative angles and angular speeds mean B minus A, clockwise positive, in radians and radians/second. Motors and forces act on physical state; they do not schedule Animated operations.

Bodies retain their active constraints. Removing a body or removing/transferring an owner from its layer disconnects them. Retained JavaScript handles remain safe and return PhysicsBody::NoPhysics for both endpoints. A retained native handle requires addRef()/release(). Constraints created before insertion stay dormant until both bodies share a world. Joining two different layer worlds throws.

Basic uses bounded impulse approximations; Chipmunk uses native constraints. Neither promises exact preservation under arbitrary loads or large timesteps. Both support force/torque caps, break thresholds and connected-body collision suppression. No response is applied when neither endpoint is dynamic.

Note
Instantiate both PhysicsBodies first. Owner updates advance constraints; calling PhysicsBody::step() on one detached body does not advance the other. Native custom worlds can call PhysicsBody::solveConstraints() with both endpoints.
const mount = sprite.createPart('mount');
const pendant = sprite.createPart('pendant');
mount.setupPhysicsBody().setMode(pdg.physicsBody_Static);
pendant.setLocation(0, 30);
pendant.setupPhysicsBody(1, 20);
const tether = mount.physics.createSpring(pendant.physics,
new pdg.Point(0, 0), new pdg.Point(0, 0), 30, 20, 5);
tether.setMaxForce(100).setBreakForce(90);

◆ setAnchors()

PhysicsConstraint setAnchors ( Point anchorA,
Point anchorB )

Move both connection points atomically.

Supports pin, slide, pivot and spring constraints. Groove and angular-only constraints throw. Both Points must have finite coordinates. Validation occurs before either stored point changes; getters report successful edits immediately.

The next physics step uses the new anchors. This includes edits requested in a collision callback: the active solver joint is not mutated during that solve. Connected sleeping bodies wake when the edit reaches the native solver. Repeating the same coordinates does not restart the joint. The public constraint handle, body endpoints, force/break limits and collision policy are preserved.

Moving anchors does not teleport bodies, change velocities, resize colliders, recalculate mass/inertia, or change a pin's distance, slide limits or spring rest length. The solver may move bodies to satisfy the new geometry. Edited anchors are saved in scene snapshots, including edits made before the next solve. A retained disconnected constraint stays editable but is not reconnected.

This edits physical connection points, not animation bones or Part offsets. Physical Part IK continues to validate its joint geometry against its Part chain; incompatible anchors produce a controller error instead of silently moving its captured chain offsets.

Parameters
anchorANew point in body A's unscaled local distance units; copied.
anchorBNew point in body B's unscaled local distance units; copied.
Returns
This constraint for chaining.
Note
The example assumes upperArm and forearm are Parts with physics bodies in the same layer, with millimeters as the application's distance unit. The coordinates are relative to each body's origin.
Example
const elbow = upperArm.physics.createPivotJoint(forearm.physics,
new pdg.Point(0, 150), new pdg.Point(0, -130));
elbow.setAnchors(new pdg.Point(0, 145), new pdg.Point(0, -125));

◆ setAngleLimits()

PhysicsConstraint setAngleLimits ( number minAngle,
number maxAngle )

Change both bounds of a rotary-limit constraint.

Both bounds must be finite and ordered; equal values lock the relative angle. Invalid input leaves both old bounds intact. Other constraint types throw. Getters and linked Part IK see the change immediately. Both physics solvers apply it on the next constraint step. This does not teleport either body or reconnect a disconnected constraint. The physical interval may span multiple turns; Part IK links accept at most one turn and report an error for a wider interval.

Parameters
minAngleMinimum body B rotation relative to A, in radians.
maxAngleMaximum body B rotation relative to A, in radians.
Returns
This constraint for chaining.
See also
getMinAngle(), getMaxAngle(), Part::setIKLimits()

◆ setGroove()

PhysicsConstraint setGroove ( Point start,
Point end )

Move both endpoints of a groove joint's track atomically.

Only groove constraints support this setter. Coordinates must be finite and the endpoints more than 1e-8 local distance units apart. Invalid input leaves both endpoints unchanged. Body B's anchor stays unchanged; use setAnchorB() to edit it. Getters report the change immediately; the solver adopts it on the next step. The same timing, lifetime and body-state rules as setAnchors() apply.
